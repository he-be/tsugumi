## 0. 結論

1. **連鎖ドラフト (d2 = MTP ヘッドの残差から [d1] をもう 1 回) の受理を影モードで測った** (§1、instruct、seed 1〜2)。d1 と d2 がともに当たる率:
   短文脈 code 0.818 / 0.818・tool 0.974 / 0.974・explain 0.538 / 0.530、12K 0.591〜0.753 (6 本)。d2 のドラフト 1 回は短文脈 12〜14 ms、12K 17 ms。
2. **検証の幅の費用** (§2): 交互の幅測定で T=3 の wall は短文脈 319〜355 ms・12K 402〜413 ms。09 §3-1 の「T=3 で pre GPU が倍」は、
   幅の順を変えると伸びる幅が入れ替わり、区間もそろって伸びるので、T=3 のカーネルの切り替えではなかった (測定の間マシンは使用中で、GPU ms は起動の間で揃っていない)。
3. **ループと巻き戻しを n_max 2 に広げ、中立だった** (§3)。`q38_gdn_step` がトークン 0 と 1 の後の状態を別々に退避し、`rollback(keep: 1|2)` で戻す。
   greedy の 3 本で、素・n_max 1・n_max 2 全部棄却・d2 だけ棄却・n_max 2 のトークン列が一致し、素と全部棄却は logit も全ステップ一致。

d2 が書く MTP の KV (位置 pos+1) は、次のステップの d1 が同じ位置を書き直すので巻き戻さない。

### 2-1. T=3 の pre GPU が T=2 の約倍になる件 (09 §3-1 の残り)

いまの形でも、この順の交互測定では T=3 の pre GPU が T=2 の 1.2〜1.8 倍になった。
区間に分けると (`Q38_SPLIT_PRE=1`、256、12 回)、特定の区間ではなく注意・GDN 入力・GDN・hc_attn/hc_ffn がそろって伸びる。
幅の順を変えると、伸びる幅が入れ替わる (GDN 入力の GPU ms、中央値):

| --- | ---: | ---: | ---: | ---: |
| 1,2,3,4 (起動 1) | 13.7 | 26.8 | 36.7 | 30.4 |
| 1,2,3,4 (起動 2) | 13.5 | 16.0 | 30.5 | 26.3 |
| 4,3,2,1 | 22.6 | 18.2 | 19.2 | 41.6 |
| 3,1,4,2 | 13.8 | 13.6 | 35.9 | 35.0 |

- dense のカーネル (`GGMLDenseGEMV`) は T によらず同じディスパッチ ((M+7)/8 × T グループ) で、MPS に切り替わるのは T ≥ 32。バッチの一時領域は decode では 32 行のまま作り直さない。T=3 でだけ落ちる経路は見つからなかった。

## 3. ループと巻き戻しを n_max 2 に (`--q38-mtp spec|reject|reject2`、`Q38_MTP_CHAIN=2`)

### 3-1. ループ (`speculativeLoop`)

1 ステップ:
1. MTP: 前のステップで受理した行 (0〜2 行、各行は受理したドラフトと、その 1 つ前の位置の幹の h) + [y, h_{pos-1}] を通し、最後の行の argmax を d1。
   続けて [d1] を位置 pos+1 で、MTP ヘッド自身の最後の行の残差と組んで通し、argmax を d2。
2. 幹: [y, d1, d2] を T=3 で通す (`allLogits`、`snapshotRows = 2`)。
3. 行 0 から t0 を引く。t0 == d1 なら行 1 から t1、t1 == d2 なら行 2 から t2。受理数 a (0〜2) で a + 1 トークンを出す。
   a < 2 なら `rollback(keep: a + 1)`。次の MTP の追いつきは受理したドラフト a 本と h_{pos}…h_{pos+a-1}、次の h は h_{pos+a}。

乱数の消費は出したトークンに 1 回ずつで、素の decode と同じ順に引く。`reject` は毎ステップ a = 0、`reject2` は d2 だけを常に棄却 (a ≤ 1)。

### 3-2. 巻き戻しの一般化

- `q38_gdn_step`: `snap_t` (1 本) を `snap_n` (0〜2) に替え、トークン 0 の後の状態を `snap`、トークン 1 の後を `snap1` (buffer 11) に書く。`rollback(keep: k)` は状態バッファを k - 1 番の退避と入れ替える (コピーなし)。
- GDN の conv 履歴: qkv の先頭 `snapshotRows` 行を blit で保存し、戻すときは退避した履歴を k 行ずらして k 行を足す。
- PLE の conv 履歴: 同じく k 行ずらして `pleNormed` の先頭 k 行を足す。`plePrev` は保存したトークンの先頭 k 本を新しい順に前へ。
- KV・インデクサの鍵・MTP の KV は位置で書き直されるので何もしない (ブロック鍵は、棄却した位置を含むブロックが次の forward の `firstBlock` 以降に入る)。
- `snapshotFirst` / `rollbackToFirst` は `snapshotRows` / `rollback(keep:)` に置き換えた (n_max 1 は `snapshotRows = 1`・`keep: 1`)。
