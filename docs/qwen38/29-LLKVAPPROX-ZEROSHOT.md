# 29. LLKVApprox の配管と zero-shot の埋め — 8K で 1.45〜1.5 倍、ツール呼び出しの分岐点が動く

実施: 2026-09-16。[28](28-LLKVAPPROX-STUDY.md) §5 の 1〜3 (配管・速度・品質の一部)。HF の投影器 (LoRA / MLP) はまだ読んでいない。
**どのセルも n = 1。** 解釈は書かず数字だけ。M6 (18 GB)、KV Q8_0、チャンク 2048、パイプライン既定、見張り (`Scripts/qwen38/guarded.sh`) 付き。
記録は `scratch/qwen38/llkv28/`。

## 0. 結論

1. **配管は正しい**: `exact` (後半層を前の行だけで別に流す oracle) は全体と教師強制 32 歩で 32/32 一致、最後の logits の max|Δ| は 0.07〜0.66 (チャンクの切り方の差、25 §2 と同じ桁)。
   分割なしの既定の経路は参照検査 6 本が PASS (誤差は 23 と同じ値)。
2. **速度 (8K)**: 全体 81.6〜83.6 s に対して zero-shot は 53.3〜58.3 s、**1.44〜1.50 倍** (28 §3 の導出値は 1.65〜1.7 倍)。埋めは 1 本 (8K) 4.3〜6.1 s。
3. **品質**: 埋め方は `hcmix` (その層の `hc_attn` で境界の残差を混ぜる) の方が `mean` (4 本の平均) より、4 本すべてで教師強制の KL が小さい。
   それでも **k6 の分岐点で P(`<tool_call>`) が動く**: 上限の行つき (k6-limit) は全体 0.4106 → hcmix 0.0001 (末尾 256) / 0.0000 (末尾 1024)。
   チェックポイント経由の探針 (末尾の正確な部分は差分の 11〜45 トークンだけ) では、行なし (k6-none) が 0.9999 → 0.6241 (16 回の抽選で呼び出し 16 → 12)。
4. 進め方は §4 (ユーザーの判断)。

## 1. 実装

- `Qwen38Runner`: `llkvSplit` (`Q38_LLKV_SPLIT`、0 = 無効)、`llkvFill` (`Q38_LLKV_FILL` = `exact` / `mean` / `hcmix`、既定 `hcmix`)、
  `llkvSuffix` (`Q38_LLKV_SUFFIX`、既定 256)。`forward(…, exactTail:)` は末尾 `exactTail` 行だけを層 `llkvSplit...` に通し、前の行は `llkvFill` で埋める。
  - 層ループの本体を `layer(il, rows:, pos:, report:)` に括り出し、層 0..<split は全行、埋め、末尾の行を先頭に詰めて (memmove) 層 split..<48 を末尾だけ流す。
  - GDN 層: `linear(recurrentOnly:)` が `attn_qkv` / `ssm_beta` / `ssm_alpha` → conv (履歴を更新) → qk norm → gates → 再帰で状態を進め、`attn_gate`・`ssm_norm`・`ssm_out` は省く。
  - 注意層: `attentionFill` が `attn_k` / `attn_v` / `indexer.k_proj` → Q8 量子化・F16 生鍵・ブロック鍵・`attnPrep` (norm + RoPE)。注意本体と `attn_output` は省く。
  - `exportHidden` (MTP) の埋めた行は境界の残差 (28 §4-2 の案 a、`exact` では最終の残差)。`exactTail` 0 (最後でないチャンク) の logits は意味を持たない。
  - 新しいカーネルは無し。
- `Qwen38Completion` と `--qwen38-generate`: `llkvSplit` > 0 のとき、プロンプトの最後のチャンクは `llkvSuffix`、ほかのチャンクは 0 を渡す。
  チェックポイント (cuts) で終わるチャンクは「最後でない」ので、全行が埋めになる。
- `TsugumiKernelCheck --qwen38-llkv-check <token file>`: 全体の prefill と、各方式 × 末尾の長さの組を比べる。
  最後の logits の max|Δ|・上位 20 の |Δ|・KL (T 0.7)・top-1・P(`<tool_call>`) と、全体の greedy 32 トークンを入力する教師強制の top-1 一致・KL。
  最後に全体をもう一度流す (温まった時間と、走行ごとの揺れ)。
