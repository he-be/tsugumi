# 23. KV を Q8_0 にして 32K へ (実施) と、強制呼び出しの文法の前置きを外す

書いた日: 2026-09-15。[22](22-KV-Q8-32K-PLAN.md) の実施記録。表記は 01 と同じ (実測 / 導出 / 未確認)。各セル n = 1 (ABBA は未実施)。
走行の記録は `scratch/qwen38/kv22/` (git 管理外)。

## 0. 結論

1. **K・V を Q8_0、インデクサ鍵を F16 にした (`Q38_KV_TYPE`、既定 `q8_0`)。** KV + インデクサ鍵は 12K で 682 → 203 MB、32K で 541 MB (MTP 層を除く計器の値)。
2. **32K で動く。** prefill 32,000 トークン 336.5 s (95.1 tok/s)、decode は MTP off 5.83 tok/s・spec 7.51 tok/s。wired 最大は off 13.07 GB、spec 14.08 GB で、12K float32 の spec (16 §0: 14.28〜14.57 GB) を超えない。
3. アプリの Qwen3.8 の文脈は 4K / 8K / 12K / 16K / 32K から選べ、新しい設定ファイルの既定は 32K。
4. **21 の 6 会話を 32K で流すと、14 ターンすべてが回答まで進んだ。文脈超過は 0。**12K (21 §9) は 12 ターン中 5 ターンが落ちていた。
5. 32K で、**強制呼び出し (`tool_choice: function:…`) のラウンドが止まらなくなる不具合**が表に出た (§4)。12K で「呼び出しが文脈の末尾で切れた」(21 §9 の S-2 候補) と見えていたものの正体。文法から前置きを外して直した。
6. 判断待ち: f32 と q8 の greedy 列が 4 本中 2 本で、ほぼ同点の位置から分かれた (§2-2)。

### 1-1. 検査

- **単体 (`--q38-kv-quant-check`)**: 1,024 行 × 256 (ガウス・外れ値・0・中間値 n + 0.5・d = 1 ちょうど・非正規化数) で、ホストの ggml 丸めと 8,192 ブロック中 0 違い。dequant・F16 の往復も 0 違い。参照器の `q8_0_roundtrip` とビット一致 (最初は -0.0 と +0.0 で 6,601 要素が違い、int8 を経由する形に直した)。
- **f32 の既存 19 本 (`checks07.sh`)**: 全部 PASS (`checks22-f32.out`)。
- **q8 の 16 本 (`checks22-q8.sh`、q8 の参照 dump に対して)**: 全部 PASS。France は最悪 7.51e-04〜8.40e-04 (基準 1e-3)。**Fuji (予算 16) の 11 本は top-1 は全部一致、logits の誤差は 2.40e-02〜3.02e-02 で、`Q38_LOGIT_TOL=5e-2` を明示した。**
  - 位置ごとでは、pos 0〜18 は 5e-4 以下、QSA の選択が始まる pos 19 で 2.65e-02、pos 45 で 1.57e-02。
  - 両側でブロックスコアを出して比べた (一時的な計器、削除済み): pos 19 と 48 は 12 層とも選択が同じで、スコアの差は浅い層で 1e-5、最終層で 3e-3。**pos 45 の 31 層だけ選択が 1 ブロック違い、参照側でもその 4 位と 5 位が 6 桁まで同点だった。**
  - f32 どうしなら 1e-7 の雑音で割れない丸めの境界が、Q8_0 の段差 (d ≈ max\|x\| / 127) をまたぐと割れ、それが選択や router の同点で増幅される形。実装の食い違いを示すものは見つかっていない。

## 4. 強制呼び出しのラウンドが止まらない (発見と修正)

### 4-1. 起きたこと

32K で 21 の 6 会話を流した 1 回目 (`tools32k`)、ja-news 3 ターン目「ここまでの内容を5行で要約して」の 1 ラウンド目 (`tool_choice: function:web_search`、prompt 18,067) で、**生成 14,700 トークン・1,425 s、stop maxTokens、呼び出し 0**。
モデルは呼び出しの代わりに 5 行の要約を書き、その後 `※` と空行を上限まで繰り返した。en-swift 2 ターン目の 1 ラウンド目 (同じく強制、prompt 4,970) も 10 分以上続き、Swapouts +25,044 ページが出たところで走行を止めた。サンプラは公式値 (0.7 / 20 / 0.8、`AppModel.makeRequest` が固定)。

### 4-2. 原因

`QwenToolCallGrammar.grammar(withPreamble:)` は、非遅延の文法 (`required` / 名前つき) の root を `!<[<tool_call>]>* tool-call` にしていた。前置きの中は文法が未完了なので停止トークンが拒否される。
回答を書き終えたモデルは終われず、`<tool_call>` を書くか上限まで何かを書くしかない。12K では残りが数百トークンで文脈の末尾に当たり、`qwen_structured_output_failure` (呼び出しが途中で切れた) や超過として報告されていた (21 §9 の ja-howto 12,199 + 88、ja-price 12,286 + 1)。

### 4-3. 修正

前置きを外し、強制呼び出しの root は `tool-call` だけにした (最初のトークンが `<tool_call>`、Gemma の強制呼び出しと同じ)。`withPreamble` 引数と `toolPreamble` を削除。Qwen3.8 は thinking を使わないので、思考ブロックの前置きも置かない。
テスト: `QwenChatGrammarBuilderTests` の「required は前置きなし」と「強制呼び出しは最初に生成される: 前に本文を置けない・呼び出しなしで止まれない・後ろに何も置けない」(`required` と名前つきの両方)。
`Scripts/test.sh --filter "TsugumiServerTests|TsugumiAppCoreTests|TsugumiDecodeServiceTests|QwenToolCall|Grammar"`: 815 件緑。
