# 04. QSA の選択ありの注意を GPU に — 選択チャンクの注意 10.6 → 1.1 s、8K で 46.5 tok/s

実測: 2026-09-13、M3 Pro 18 GB、macOS 15。対象は [03](03-PREFILL.md) と同じ GGUF・ランナー・プロンプト (`scratch/qwen38/prompt-code.tokens`)。
表記は 01 と同じ (実測 / 導出 / 未確認)。**速度の行はどれも n=1 で、数字だけを書く。**

## 0. 結論

1. **T ≥ 32 のバッチで QSA の選択が要るとき、host のソートと 5 パスをやめた** (`Qwen38Runner.attentionSelected`)。
   インデクサのスコアは sgemm、top-k は GPU のビット二分探索、注意はサブバッチ (既定 64 クエリ) ごとに「選ばれたトークンの和集合」だけを集めて sgemm、選ばれていない列はマスク。
   T < 32 (decode を含む) は従来の host 経路のまま。`Q38_ATTN_MPS_MIN_T=0` で全部を従来経路にでき、これをオラクルに使う。
2. **正しさ**: 参照 (Fuji 予算 16) とチャンク 53 で 53/53・logits ≤ 2.26e-6。同じ層入力に新旧両方を流した比較で、4K の選択チャンク 12 層すべて `ao` の相対差 ≤ 7.0e-6 (§2)。
   同点の規則 (小さいブロック番号が勝つ) は合成スコアで host のソートと一致 (§2-1)。
3. **速度** (8,192 トークン、チャンク 2048、§3):

   | | 03 (host 選択 + 5 パス) | 04 |
   | --- | ---: | ---: |
   | 選択ありチャンクの注意 (GPU) | 10.6 s | **1.1〜1.8 s** |
   | 8K 全体 | 199.7 s (41.0 tok/s) | **176.1 s (46.5 tok/s)** |
   | peak footprint | 3.04 GB | 3.36 GB |

4. 残る 1 チャンク (約 45 s) の大半は **routed の wall 28〜29 s (GPU 13.9 s、差は読み待ち)**、route 4.6 s、GDN 5 s。次は 03 §6-3 の 2 番 (routed の読み) から (§4)。

## 1. 形

1 層の流れ (`attention` → `attentionSelected`):

1. **インデクサのスコア**: `iq [T×4][128]` × `blockKeys [nb][128]ᵀ` を sgemm (点積の一時領域が 64 MB 以内になるようクエリを分割)、`q38_idx_relu_sum` で `score[t][b] = Σ_h relu(·)`。
   従来の `q38_idx_score` は 1 スレッドで 4×128 のループだった。
2. **top-k** (`q38_idx_topk`、クエリごとに 32 レーン): スコアは relu の和で ≥ 0 なので、float のビット列の大小が値の大小と一致する。
   - 「`#(bits ≥ v) ≥ k` を満たす最大の v」をビット 30→0 で決める = k 番目に大きい値 `thr`。
   - `need = k − #(> thr)`。同点が `need` より多いときだけ、「`#(== thr かつ b < c) < need` を満たす最大の c」を 21 ビットで決める = 最後に選ぶ同点ブロック `cut`。
   - 選択は `bits > thr`、または `== thr` かつ `b ≤ cut`。`n ≤ k` の行は `thr = 0, cut = n` で全選択。並べ替えは無い。
3. **和集合** (`q38_idx_union`): サブバッチ (`Q38_ATTN_SEL_B`、既定 64) ごとに、どれかのクエリが選んだブロックを 1 バイトで。ここで 1 回 commit して host が読む。
4. **トークン列** (host): 和集合のブロック (先頭クエリの未完ブロックより前) + そこから最後のクエリまでの全トークン。256 の倍数に `~0` で詰める (MPS の形の数を抑えるため)。
5. **注意** (KV グループ × サブバッチ): Q を集める → `q38_attn_gather_kv_list` で K・V を列から集める → `Q Kᵀ/√D` を sgemm →
   `q38_attn_mask_sel` で「そのクエリが見ないトークン」(未来・詰め物・選ばれていないブロック) を −FLT_MAX → 既存の max・Σexp・重みのカーネル → `W V` を sgemm → ゲートを掛けて散らす。

和集合の大きさ (従来経路で host 選択から数えた、4K プロンプトの 2 チャンク目、n = 4,096、1 クエリの選択は 2,051):

| サブバッチ | 平均 | 最大 |
| ---: | ---: | ---: |
| 64 | 3,028〜3,072 | 3,872〜4,000 |
| 256 | 3,184〜3,199 | 4,020〜4,096 |
| 1,024 | 3,584 | 4,096 |
| 2,048 | 4,096 | 4,096 |

近いクエリどうしでも選択はかなり違う。和集合で節約できるのは n = 4K で 1.3〜1.5 倍ぶんだけ (導出)。n × 全幅のマスク (03 §6-3 の案) は 32K の最後のチャンクで選択 2,051 列の約 16 倍の FLOPs になる (導出) ので、和集合の形にした。

## 2. 正しさ

| 検査 | top-1 | logits / `ao` 最悪 |
| --- | ---: | ---: |
| prefill Fuji 予算 16、チャンク 53 (新経路) | 53/53 | 2.26e-6 |
| 同、`Q38_ATTN_SEL_B=1` / `7` (サブバッチを分ける) | 53/53 | 2.31e-6 / 2.26e-6 |
| 同、`Q38_MPS_MIN_T=16 Q38_ATTN_MPS_MIN_T=16`、チャンク 16 | 53/53 | 1.78e-6 |
| 同、`Q38_ATTN_MPS_MIN_T=0` (従来経路) | 53/53 | 2.48e-6 |
| 同じ入力で新旧の `ao` (`Q38_ATTN_SEL_COMPARE=1`)、Fuji チャンク 53、12 層 | — | 相対 ≤ 2.0e-6 |
| 同、4K プロンプトの 2048..<4096、12 層 | — | 相対 ≤ 7.0e-6 (絶対 ≤ 1.6e-5) |

03 §6-2 の検査一式は全部 PASS のまま。

### 2-1. 同点 (`--q38-select-check`)

モデルのスコアは同点になりにくいので、合成スコアで `q38_idx_topk`・`q38_idx_union`・`q38_attn_mask_sel` を host の規則 (スコア降順、同点はブロック番号昇順で先頭 k) と比べる。
スコアは 0〜3 の整数 (同点だらけ)、9 割が 0 (relu)、連続値の 3 種。k・位置・T は (16, 0, 200)、(16, 60, 150)、(5, 1000, 97)、(512, 3000, 300)。12 通りすべて行・和集合・マスクが一致。

### 2-2. 端から端の比較は長文脈の検査にならない

4K を新経路と従来経路 (`Q38_ATTN_MPS_MIN_T=0`) で流して最後の logits を比べると、top-1 は同じで相対差は 1.87e-2 (prefill の最後)・2.46e-2 (続く decode)。
ただし選択の無い 1 チャンク目 (5 パスと sgemm の違いだけ) で、もう expert の異なり数が違う (19,183 / 19,194)。
同じ入力での `ao` の差は ≤ 7e-6 なので、この差は 48 層と router の top-10 を通った増幅と見ている (これ以上の切り分けはしていない)。
長文脈の新経路を確かめるには、同じ入力での比較 (`Q38_ATTN_SEL_COMPARE=1`) を使う。

## 6. 落とし穴 (このセッションで踏んだもの)

- **新旧を同じ入力で比べるときは、in place で書き換えるバッファを戻す。**`q38_attn_prep` は KV キャッシュのバッチ行を、`q38_idx_q_prep` は `iq` を、どちらも in place で RoPE する。
  `iq` を戻し忘れると 2 回回った RoPE で選択がずれ、`ao` の相対差が 1e-1 になる (新経路が壊れたように見える)。
- MSL に `bitcast` は無い。float のビットは `reinterpret_cast<device const uint*>` で読む。
- `simd_sum` を 1 関数の中でループの中に何度置いてもよい。レーン間で分岐が揃っていれば (条件が `simd_sum` の結果だけに依るなら) 正しく動く。
