# 37. 仕切り直し — PC の UD-Q4_K_XL で、まずデータを取る (33〜36 の整理)

書いた日: 2026-09-18。表記は 01 と同じ (実測 / 導出 / 未確認)。この文書を書いた時点では、新しい測定は何もしていない。

33〜36 の 4 本は 2 日で書いた。その間に、測る環境を「Mac の過去の記録」→「PC の Q2_0」→ (打ち切り) と 2 回変えている。**今後の計画はこの文書だけを見る。** 33〜36 は記録として残し、それぞれの冒頭に今の状態を書いた。

この文書で使う言葉。

- **測定環境**: どのマシンの、どのサーバで、どのモデルを動かして測るか。この文書では PC の llama-swap で動かす `qwen3.8-flash-next-q4kxl-32k-instruct-bf16ple` を指す (§2)。
- **変更案**: ツールの結果の渡し方など、ラウンド数を減らすために試す変更 (33 §3 の R1-a・R1-c)。
- **揺れの幅**: 何も変えずに同じ条件を 2 セット流したときの、数字の差。PC のサーバは実行ごとに出力が揺れるので (32 §4-1)、変更案の効果はこの幅より大きいときだけ効果として扱う。

## 0. 決めたこと (2026-09-18、ユーザー)

1. **Q2_0 (ISTA の GSQ-RCO) は使わない。** ツールのループは最後まで動いたが、日本語の文章が壊れている (36 §2)。
2. **Mac 用の GGUF を llama.cpp で動かす作業はしない。** Mac 用の GGUF は `general.architecture = qwen4exp` で、down 射影を 768 に詰め、PLE 表を別の GGUF に分けてある。どれも llama.cpp の標準の読み込みでは通らない (35 §0-1)。PC で Mac と同じ重みを動かすことは、当面あきらめる。
3. **モデルの挙動 (ラウンド数、どのツールをどの順で呼ぶか、回答) を Mac で評価しない。** Mac では 1 回の反復に時間がかかりすぎる。Mac で行うのは、速度の測定と、我々のランナーでしか動かないものだけにする。具体的には、prefill の計測 (33 §4 の P)、LLKVApprox の組み込みと品質確認 (33 §5 の K3・K4)、この文書 §3-3 の Mac での確認。
4. **挙動の評価は PC の UD-Q4_K_XL で行い、まずデータを取る。** モデルは 32 §4-1・§5 と同じ `qwen3.8-flash-next-q4kxl-32k-instruct-bf16ple`。変更案を試す前に、今のアプリの形でのベースラインと揺れの幅を取る。

## 2. 測定環境 (PC、UD-Q4_K_XL)

- サーバ: 192.168.0.199 の llama-swap。**接続先は Tailscale の `http://100.121.61.11:8080`。** `192.168.0.199` には、macOS のローカルネットワーク許可のせいで Swift / Python から繋がらない (36 §0)。
- モデル: `qwen3.8-flash-next-q4kxl-32k-instruct-bf16ple` (unsloth UD-Q4_K_XL、PLE 表は BF16、MTP なし、32K)。PLE 表の型を比べたいときは、Q4_1 の PLE 表を使う `-q4ple` もある (32 §4-1)。
- サンプリング: 公式値のまま (temp 0.7 / top_p 0.8 / top_k 20 / min_p 0 / presence 1.5)。thinking off。変えない。
- 道具: `TsugumiToolLoopCheck --endpoint … --remote-model …`。ローカル Wikipedia と Web のツールは Mac 側で実行し、推論だけを PC に投げる。Online では `--pin-search --search-budget 0` で、保存しておいた検索結果を返す。**Serper は 1 回も呼ばない。**
- 注意: このサーバは、同じトークン列を入れても実行ごとに logits が揺れる (32 §4-1)。長く流し続けて llama-server が落ちたこともある (502、32 §4-1)。`turns.jsonl` の error と空の answer を見て、無効な回は除く。

### 2-1. Mac との違いとして受け入れること・受け入れないこと

変更案どうしは同じ PC の環境で比べるので、次の違いは受け入れる。

- 本体の量子化の型が違う (PC は UD-Q4_K_XL、Mac は IQ2_XXS + 詰めた down の Q2_K)。
- PLE 表は、どちらも BF16 で型は同じ。ただし同じ表かどうかは確かめていない。
- KV の型と文脈長は Mac に合わせる (q8_0、32K)。

次のことはしない。

- PC で測った時間を、Mac での時間の代わりにする。
- PC で出た変更案の効果を、Mac で確かめずに採用する。PLE 表を変えただけで開くページが変わった例がある (32 §4-1) ので、PC の結果が Mac でも同じになるとは限らない。
- 1 セットだけで出た差を、変更案の効果として読む。同じ条件を 2 セット流した差 (揺れの幅) を超えたものだけ効果とする (32 §5-4)。
- 日本語が崩れるモデルで測る。Q4_K_XL でも中国語の語が混じることはある (36 §2-2、10 回答中 2) が、Q2_0 のように文章そのものが崩れてはいない。

### 3-1. W1: ベースラインと揺れの幅 (PC)

流す課題。

- **Offline**: `docs/experiments/knowledge-sources/questions-v2-stage2.json` の N1〜N5 (正解は `answer-notes-v2.md`)。33 で追加するとしていた「正解のある、2 つの記事にまたがる課題 15 問」は作らない (原理的に作れない)。
- **Online**: `docs/experiments/first-fetch/questions.json` の 40 問と、保存済みの検索結果 (32 §5、`…/7f01f2ec-…/scratchpad/firstfetch/web/pinned`、40 本)。32 §5 は 2 ラウンド目で止めていた (`--stop-after-round 2`) が、**W1 では回答まで流す** (`--max-rounds 6`)。

流し方と出す数字。

- 各条件で、**別々に 2 セット**流す。1 セットは、1 問につき N 回。N は 5 以上。
- 出す数字: ラウンド数の分布、ラウンドの種類ごとの本数 (`Scripts/qwen38/round_breakdown.py --run LABEL=DIR` で `rounds.jsonl` を数える)、生成トークンの合計、正答数、所要時間 (PC 上の実時間)。
- **揺れの幅**: 同じ条件の 2 セットの差。R1 以降は、この幅を超えた差だけを変更案の効果として扱う。

所要時間の見込み (導出。36 §1 の Q4_K_XL の 1 セットでは 5 問で 184 s / 175 s、1 問 35〜37 s。ラウンドの上限は 6)。

| 条件 | 問 | N | 1 セット | 2 セット |
| --- | ---: | ---: | ---: | ---: |
| Offline | 5 | 10 | 約 31 分 | 約 1 時間 |
| Online | 40 | 5 | 約 2 時間 | 約 4 時間 |

- 繰り返して測った参考値: iPhone 18 の 1 問を 20 回流して 4〜7 ラウンド、平均 4.35 / 4.40 (32 §4-1、PLE 表が Q4_1 / BF16)。
- 36 §1 の Q4_K_XL の 1 セットずつ (Offline 23 ラウンド / 184 s、Online 5 問 23 ラウンド / 175 s) は、ツールのループが最後まで動くことの確認として扱う。1 セットしかないので、ラウンド数の比較には使わない。

### 3-2. R1: 変更案 (実装は Mac、測定は PC)

変更案は 33 §3 のまま。W1 の「ラウンドの種類ごとの本数」を見て、多い種類に効く案から 1 つずつ試す。

- **R1-a 強制した検索の結果に、上位 k 件のページの目次を添える** (k = 1、2、3 をそれぞれ試す)。狙いは、強制の `fetch_page` と、その後に同じページの節を読みに行くラウンドを、1 往復にまとめること。
- **R1-c Offline の検索結果に、記事の冒頭の数文と目次を添える。** R1-a の Offline 版。
- R1-b (1 ラウンドで複数のページを開く) は、まとめて 1 つの結果として返す処理がすでにあることを 34 §3 で確かめた。ただし実行は 1 本ずつ順番で、その待ち時間は記録に無い (未確認)。試す変更案には入れない。

どの案でも、ツールの宣言を会話の途中で変えない。プロンプトの文言で呼び出しの確率を下げる案は入れない (26)。各案とも、W1 と同じ数字を 2 セット分出す。

### 3-3. M: Mac での確認

揺れの幅を超えた変更案だけ、Mac で Offline 5 問 × 2 回流す。見るのは `turn-metrics.jsonl` の秒・pp・tg・読み込み量・wired の最大・swapout。ここで初めて「Mac で速くなったか」を言う。

## 4. 再現の形

```
.build/release/TsugumiToolLoopCheck --out DIR --model ~/LLM/Qwen3.8-Flash-Next-DS4-IQ2 \
  --conversations docs/experiments/knowledge-sources/questions-v2-stage2.json \
  --network offline --max-rounds 6 --thinking off --context 32768 --repeats N \
  --endpoint http://100.121.61.11:8080 --remote-model qwen3.8-flash-next-q4kxl-32k-instruct-bf16ple

.build/release/TsugumiToolLoopCheck --out DIR --model ~/LLM/Qwen3.8-Flash-Next-DS4-IQ2 \
  --conversations docs/experiments/first-fetch/questions.json \
  --network online --max-rounds 6 --thinking off --context 32768 --repeats N \
  --web-store STORE --pin-search --search-budget 0 \
  --endpoint http://100.121.61.11:8080 --remote-model qwen3.8-flash-next-q4kxl-32k-instruct-bf16ple

python3 Scripts/qwen38/round_breakdown.py --no-app --run "W1 offline set1=DIR" --sequences
```

- `--web-store` には 32 §5 の保存済み検索結果の置き場を指定する。どの変更案でも同じものを使う。
- 実行の記録 (`rounds.jsonl` / `turns.jsonl` / `run.log`) はセッションの一時ディレクトリに置く。リポジトリに入れるのは集計した表だけ。
