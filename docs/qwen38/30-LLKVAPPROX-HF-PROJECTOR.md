# 30. HF の KVA 投影器を読む — 形は一部しか決まらず、うちの値に対しては hcmix より外れる

実施: 2026-09-16。[29](29-LLKVAPPROX-ZEROSHOT.md) §4 の A (ユーザーの選択)。
投影器を実行時に足す前に、うちのランナーの正確な値と突き合わせて形を決め、効くかを見る段。**ランナーへの組み込みと k6 の再測定はしていない** (§4)。
数字は 1 プロンプト (prompt-code の先頭 512 トークン、1 チャンク) の行平均で、n = 1。記録は `scratch/qwen38/llkv28/dump512`・`fit512.txt`。

## 0. 結論

1. HF の `projector.safetensors` (144 本、bf16) に入っているのは、GDN 18 層の LoRA (qkv / b / a) と FA 6 層の MLP (k / v / ik) だけで、bias も norm も無い。
   エンジンのコードは非公開で、入力の正規化・MLP の活性化・K のノルムの前後はファイルにも PR #45 にも無い。
2. うちの値で決まったこと:
   - ヘッドの入力は **境界の残差をそのまま** (コピー順 [4][2560] を平らに、norm なし)。v・b・a の出力が目標と揃うのはこの読み方だけ (§2)。
   - GDN の v・b・a の出力は **HF のグループ順の値ヘッド** (キーのグループ g の 3 本 = HF 3g + r)。GGUF (llama.cpp の変換) は 16r + g に並べ替えているので、動かさないとコサインは 0.00〜0.05、動かすと 0.51〜0.88。
   - qkv の q の部分は出力が 0 (学習対象外)。
   - 土台の「自層の射影をコピーの平均に」は norm なしだと本物の層入力より 17〜35 倍小さい (うちの層入力は RMS norm の後)。HF のヘッドの出力は、残差 (目標 − 土台) とも目標そのものともほぼ同じコサインで揃う (層 24 v で 0.654 / 0.655)。小さい土台に対して目標の大部分を出す形と読める。
3. **決まった形で足しても、うちの値には hcmix (29 の zero-shot) より外れる**。90 の目標 (GDN 18 層 × k / v / b / a、FA 6 層 × k / v / ik、FA は SiLU) の平均コサインは
   土台 0.735、**hcmix 0.835**、土台 + HF ヘッド 0.625、倍率を最小二乗で当てても 0.805。土台 + HF ヘッドが hcmix を上回るのは 4 目標 (L44 a、L46 b / a、L47 v) だけ。
   PixelML の held-out は FA k 0.945〜0.953、GDN k 0.978〜0.982。
4. 原因の切り分けはしていない (§3)。進め方は §4 (ユーザーの判断)。

## 1. 手順

- `TsugumiKernelCheck --qwen38-llkv-dump <token file> <dir> --q38-tokens 512`: 同じ 512 トークンを 3 回 (全体、`mean` の埋め、`hcmix` の埋め)、
  境界の残差 (層 23 の後) と層 24... の入力射影を書き出す。GDN は `attn_qkv` / `ssm_beta` / `ssm_alpha` の出力 (gates の前、`gdn_in` の区切りで読む)、
  FA は `attn_k` (norm の前) / `attn_v` / `indexer.k_proj` の出力。ほかに層 24... の `attn_k_norm` / `indexer.k_norm`。
  `Qwen38Runner.llkvDumpDir` (`splitPreRouter` が要る)、`f32Values`。512 トークンで 12.1 / 6.2 / 6.4 s、Swapouts 0。
- `Scripts/qwen38/llkv_projector_fit.py <dir> <projector>`: bf16 はビットを 16 ずらして f32 に。行ごとのコサインで、土台 (`mean`)・`hcmix`・土台 + ヘッド・a × 土台 + b × ヘッド (a, b は全行の最小二乗) を出す。
- `projector.safetensors` 385,022,744 バイト (ヘッダの申告と一致) と PR #45 のノートブック・receipts は `~/LLM/Qwen3.8-KVA-Projector/`。

## 2. 形を決めた経緯 (層 24 / 40 中心)

| 読み方 | GDN v: cos(目標, ヘッド) | b | a | k: cos(残差, ヘッド) |
| --- | ---: | ---: | ---: | ---: |
| 残差そのまま、値ヘッドはそのまま | 0.045 / 0.005 | 0.321 / −0.037 | 0.111 / 0.172 | 層 24 0.106 |
| 同、コピーの 24 通りの並べ替え | 最大 0.044 (層 24) | | | |
| 同、次元順 [2560][4] | 0.011 (層 24) | | | |
| コピーごと RMS norm (γ なし / 層 24 の γ / 自層の γ)、全体 RMS norm | 0.00〜0.05 | | | |
| **残差そのまま、値ヘッドを HF のグループ順から GGUF の順へ** | **0.655 / 0.697** | **0.878 / 0.800** | **0.577 / 0.509** | |

(層 24 / 層 40。値ヘッドを逆向きに並べ替えると 0.041 / 0.030)

- 大きさ: 残差のコピー 1 本のノルムは中央値 1.3〜2.4 (行 0 は 12.4)、層入力の射影 (qkv の v) は 70 前後。
  全体を RMS で割った入力では、ヘッドの出力が v で 800〜2,400、b で 250 前後と目標 (72、12) の数十倍になり、残差そのままなら v で 30 前後。
- 最小二乗の倍率: 土台 a は GDN で主に 17〜35 (L44 b 11.5、L45 k 14.2、L46 a 4.9)、FA で 5〜12。ヘッド b は 0.07〜3 (1 から離れる)。
- FA の活性化: none / ReLU / GELU / SiLU の差はコサインで 0.03 以内 (GELU と SiLU がわずかに上)。K を norm の後で比べても差は変わらない (層 27 の k で土台 0.707、+ ヘッド 0.53〜0.54)。

## 3. 分かっていないこと

- 外れる理由。候補は、重みの違い (HF は AWQ-INT4 の bf16 化、うちは IQ2_XXS / Q2_K で、層 0..23 を経た境界の残差からして違う)、入力や目標の読み違いが残っていること (K の目標がノルムの前か後か、b / a の名前の対応、FA の活性化)、学習量 (16 × 2,048 トークン)。
  どれかを確かめるには、HF 側で同じプロンプトの値を作る必要があり、うちの 18 GB では HF の参照を動かせない (28 §2)。
- 512 トークン 1 本だけの数字。長さ (位置) による差は見ていない。

## 4. 次の段 (判断待ち)

- **A'. それでもランナーに組み込み、k6 (29 §3) を測る**: ヘッドの読み込み (F16 で約 385 MB) と、GDN の LoRA・FA の MLP (SiLU で仮置き) の GEMM、値ヘッドの並べ替えを足す。§0-3 の数字からは、hcmix より悪くなる見込み。
- **B. hcmix のまま測り足す** (29 §4 の B): greedy 200、32K の速度、ツールループ検査。29 では k6 の分岐点が動いた。
- **C. 自前で投影器を学習する**: 目標はこの文書のダンプ形式でうちのランナーから作れる (512 トークンで約 12 s)。学習はこの機械では同居できない (28 §2)。
- **D. LLKVApprox はここで止める**。

## 5. 学習する場合の見積もり (導出、実測なし) と打ち切り

2026-09-16、ユーザーの判断で **LLKVApprox はここで打ち切り**。コードは既定で無効 (`Q38_LLKV_SPLIT` 未設定) のまま残す。

要点 (28〜30):

- 速くはなる: 8K の prefill が約 82 s → 約 55 s (1.5 倍、29)。
- 重みなしの埋め (`hcmix`) は、ツールを呼ぶかどうかの判断 (k6 の P(`<tool_call>`)) を変える (29)。
- 公開の学習済み投影器は、うちの Q2 のモデルに対して `hcmix` より外れる (この文書)。
- 残る手は、うちのモデル用に投影器を自分で学習すること。

学習に要るもの (もし再開するなら):

| 項目 | 見積もり | 根拠 |

| VRAM / 統合メモリ | 約 6〜8 GB | 192.5M パラメータの重み・勾配・AdamW 状態で約 3 GB、2,048 トークンのバッチの途中の値で 2〜4 GB (GDN の qkv 出力 10240 × 2048 × 18 層など) |
