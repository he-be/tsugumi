## 0. 結論

1. **壁時計 (c) は、同じバイナリの交互で 1.937 → 1.857 s** (各 n = 6、6 組すべてで短い)。台帳の行は 1.914 → 1.768 s。
2. 1 run の Pageins は変わらない (既定 2.8〜3.3 GiB、候補 3.0〜3.4 GiB)。読む量は同じで、GPU が SSD を待つ区間が縮んだ: `l1-host-advise` の 2・3 本目で GPU の空き 0.392・0.337 s (40 の既定は 0.424〜0.455 s)、そのうち `fetch` の間 0.329・0.288 s (同 0.372〜0.400 s)。
3. 計算は変わらない。greedy 64 トークンの本文は 2 本とも `c0707c48e5`。

## 2. routed MoE の 32 行のタイル (候補、既定に入れない)

nax (40) を行の断片数のテンプレートにし、32 行以下のブロックを `prefill_moe_gemm_int4_nax_m32` に回す (28 の mpp の M32 と同じ分け方)。KernelCheck の `nax-64/32 vs mpp` は 811008 要素すべて一致。
単体 (`moe-gemm-bench-nax32-2`、gate/up、µs): 12 行 477.5 → 386.1、27 行 520.6 → 458.6 と縮むが、96 行 1012.4 → 1168.6、140 行 1507.9 → 1682.2、155 行 1621.6 → 1773.8 と伸びる (64 と 32 の 2 段を別の dispatch で流すため)。
縮むのは主にチャンク 2 (1 expert 平均 27 行) で、見込みは 0.02 s 程度 (導出) と揺れの幅より小さいので、壁時計は取っていない。
