# 41. エキスパートのページを層ごとに先読みする・1 周で済ませる — どちらも SSD の読みを減らさない (実測、2026-09-25)

**候補の測定。台帳 §1 は動かない。ソースは戻した** (c4f33ea・3537b23 を 9a0d4cd・a7d256f で revert)。
[40 §3](40-MOE-GEMM-NAX.md) の既定の上で、GPU の空き 0.42〜0.46 s のうち 0.37〜0.40 s は、層ごとのエキスパートのページを SSD から待つ区間だった。
2 つの見立てを確かめた。

- **A. 次の層を先に頼む**: prompt のチャンクは 1 層のほぼ全エキスパートに振られるので、routing を待たずに次の層を頼める。層の頭で N 層先の全エキスパートに `F_RDADVISE` を出す候補 (`TF_PREFILL_ADVISE_AHEAD=N`、c4f33ea。3537b23 で advise を streamer のキューから外した)。
- **B. 2 周目の読み直し**: チャンク順 (チャンク 1 で 30 層 → チャンク 2 で 30 層) だと、エキスパートを 1 run で 2 周なめる。2 周目が SSD から読み直しているなら、層順に組み替えると読みが減る。組み替えの前に、1 チャンクに収まる本文 (`bench/m6/l-1chunk.json`、1963 トークン) で 1 run の Pageins を比べた (`TF_BENCH_MESSAGES`、f96892d)。

証拠 (M6、`bench/m6/results/2026-09-25-Mac18-5-<ラベル>/`): `v1-{default,ahead1,ahead2}-{a,b}` (3 腕を 2 巡交互に、各 n = 3)、`v2-host-ahead1`、`p1-one-chunk`。台帳の比べ先は [40](40-MOE-GEMM-NAX.md) の `ledger-moe-nax`。

```
測定: 2026-09-25 / Mac18,5 Apple M6 16GB / macOS 27.0 (26A428) / Swift 6.4 / SDK 27.0 / CLT / APPLE SSD AP0256Z / commit c4f33ea〜f96892d (各ディレクトリの hostinfo.txt) / minos 15.0
```

コマンドは台帳の固定形 (`prefill_bench.sh`)。`p1-one-chunk` だけ本文が `bench/m6/l-1chunk.json`。全 run exit 0、Swapouts 0。
Pageins は各 run の前後の `vm_stat` の差 (16 KiB ページ、導出)。

## 0. 結論

1. **A は遅くなる。**壁時計 (c) は既定 1.909〜2.071 s に対し、深さ 1 で 2.506〜2.837 s、深さ 2 で 2.606〜2.911 s。1 run の Pageins が 3.0〜3.3 GiB から 7.5〜8.9 GiB に増えた。キャッシュ (M6 の File-backed pages は 11.2 GB) がモデル (15.7 GB) より少し小さいところで 1 層ぶん先に読むと、あとで当たるはずだったページを追い出して読み直しが増える、と読む。
2. **B は外れ。**1 チャンク (1963 トークン) の 1 run の Pageins は 2.8〜3.5 GiB で、2 チャンク (台帳、2478 トークン) の 2.7〜3.3 GiB (1 本目を除く) と変わらない。2 周目はほとんど SSD を読んでいない。層順に組み替えても SSD の読みは減らないので、組み替えはしない。
3. 1 run で約 3 GiB を SSD から読むのは、今のメモリの条件 (16 GB、モデル 15.7 GB) の前提と置く。M6 の SSD (3.3 GB/s) で約 0.9 s (導出) で、そのうち GPU の計算と重ならない分が GPU の空き 0.4 s として出ている。
