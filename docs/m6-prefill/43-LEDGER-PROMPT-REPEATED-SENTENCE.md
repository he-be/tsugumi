## 0. 結論

1. **台帳の本文 `bench/l.json` は、同じ 1 文 (「チャンク化した prefill が…説明してください。」) を 50 回繰り返して末尾に 1 行足したものである。**36〜42 はこの本文だけで測り、[29](29-REFERENCE-RUNTIMES-ON-M6.md) の mlx_lm・llama.cpp との比較もこの本文だけで取った。
2. **自然文では同じ長さでも prefill は 2.6〜5.5 s。**既定 (feca5d5 と同じソース) で `ja-twomachine` 2.595 s、`ja-m6readme` 3.441 s、`en-readme` 4.407 s、`en-server` 4.568 s (§1)。`l` は同じ条件で 1.885 s。サーバ経由でも同じ形 (`l` 2.519 s、他は 4.19〜5.00 s)。
3. **差は SSD の読みである。**1 run の Pageins は `l` 3.5 GiB に対し、自然文は 5.9〜12.0 GiB。フッタの expert io も 0.66 s に対し 1.4〜4.2 s。取得したエキスパートの数は 5763 に対し 6310〜6959 で 2 割しか違わないので、増えたのは「読み直す量」である (読み: 同じ本文を続けて流すとその本文のページがキャッシュに残るが、自然文の足あとは残らない)。M6 の SSD 3.34 GB/s ([03](03-FACTS.md)) なら 12 GiB は約 3.9 s (導出) で、`en-server` の 4.6 s の大半を占める。
4. **36〜42 のカーネルの変更は自然文にも効いている**: `old` (36〜42 を環境変数で戻した構成) → 既定で、`ja-twomachine` 3.859 → 2.595 s、`en-readme` 5.444 → 4.407 s、`en-server` 5.444 → 4.568 s。42 (`noadv` → 既定) も `ja-m6readme` で 4.098 → 3.441 s。縮んだ秒は本物で、取り下げるのは「到達目標を下回った」という判定と、`l` で測った台帳の量である。
5. **到達目標の比較は成り立っていなかった。**mlx_lm と llama.cpp は重みを全部載せる (MLX はスワップしてでも) ので、本文の足あとで秒が変わらない。Tsugumi はエキスパートを SSD から流すので、足あとが小さくキャッシュに残る本文でだけ速い。**繰り返し文で「同じ本文で下回った」と書いたのは、Tsugumi の主な代償が見えない本文を選んで比べたことになる。**目標そのもの (1.823 s) は動かさない。比較は自然文で取り直す (§3)。

## 2. 何が間違っていたか

1. **本文を一度も見ていなかった。**`bench/l.json` は MBP 時代のデコード用ハーネス (5ebc18c) から引き継いだもので、M6 の計画 (10〜42) はその中身を確かめずに「2478 トークンの本文」と呼び続けた。
2. **同じ本文を続けて流す計測は、その本文のページキャッシュを暖める。**[06 規則 5](06-LEDGER.md) は「その run のページキャッシュの状態は含む」と書いたが、含まれていたのは「直前に同じ本文を流した後の状態」で、利用者が違う本文を送る状態ではない。[41 §0-3](41-SSD-READ-AHEAD.md) の「1 run で約 3 GiB を SSD から読むのは前提と置く」は、この本文だけの値を一般化していた。
3. **比較相手は本文の足あとに依らない実装だった。**§0-5。
4. **42 の判定「到達目標を下回った」は、台帳の量が繰り返し文だったから出た。**42 の秒の縮み自体は自然文でも出ている (§0-4)。

## 3. 以降の規則 (04・06 に反映)

1. **台帳の本文は自然文にする。**`bench/m6/prompts/` の 5 本 (`ja-twomachine`、`ja-m6readme`、`en-readme`、`en-server`、`code-runner`) を 1 組とし、run ごとに本文を替えて回す (同じ本文を続けて流さない)。台帳の行は本文ごとの中央値を並べる。`l` は繰り返し文の列として残してよいが、進捗と目標の判定には使わない。
2. **本文ごとに 1 run の Pageins と expert io を表に添える。**秒が縮んだとき、読む量が減ったのか、計算が縮んだのかを分ける。
3. **到達目標の比較 (mlx_lm、llama.cpp) は自然文の同じ組で取り直す。**取り直すまで、README の「下回った」は無い。
4. **`ledger-*` の行のうち `bench/l.json` で取った行 (ef29110〜619c515) は、繰り返し文の履歴として残し、進捗の物差しにしない。**次の既定の行は規則 1 の形で取る。
5. **ベンチ用の本文を新しく置くときは、中身 (何の文章か、繰り返しがあるか) を文書に 1 行書く。**
