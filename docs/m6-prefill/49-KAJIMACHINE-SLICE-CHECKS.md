## 0. 結論

1. **M6 にログインし、Chrome と Web カメラ (Iriun) を起こした状態でも、80 個版は 1 回 8.09 s で動く。**`iogpu.wired_limit_mb` は再起動後の既定 (0) のまま。エラー 0。
   ヘッドレスの 7.54 s ([48](48-KAJIMACHINE-EXPERT-SLICE.md)) との差は 0.55 s。Swapouts は 1 周目に 78,256 ページ出て、2 周目は 0。
2. **残すリストは写真を増やしても変わらない。**選ぶ用を 48 → 96 → 192 → 364 枚にしても、確かめる用の 96 枚で残る選択は 0.9726 → 0.9727。48 の版と 364 枚の版は層ごとに平均 79.3 / 80 個が同じ。
   日付で前後に分けても、日ごとに除いても 0.971〜0.973。**選び直さない。**
3. **英名の崩れは、スキーマの `maxLength` で消える。**英名の文字列に `maxLength` 100 を足すと、480 回で 10 → 0。生成は最大 52 トークンで止まる。
4. **サンプリングでは減らない。**repeat penalty 1.05 / 1.10 と presence penalty 0.5 は 14 / 20 / 22 に増え、DRY 13、temperature 0.7 と top-p 0.9 は 9 (基準 10、各 480 回)。

## 3. 英名の崩れを止める (jenga、80 個版、48 と同じ 96 枚の英名だけ × 5 回、[`item_rate.tsv`](../../bench/m6/results/2026-11-15-jenga-kj-item-maxlength/item_rate.tsv))

| 要求に足したもの | 回数 | 読めない答え | 生成トークンの中央値 / 95% 点 / 最大 |
| --- | ---: | ---: | --- |
| なし | 480 | 10 | 29 / 40 / 120 |
| **英名のスキーマに `maxLength` 100** | 480 | **0** | 29 / 37 / 52 |
| `repeat_penalty` 1.05 | 480 | 14 | 29 / 66 / 120 |
| `repeat_penalty` 1.10 | 480 | 20 | 29 / 113 / 120 |
| DRY (`dry_multiplier` 0.8) | 480 | 13 | 28 / 39 / 120 |
| `temperature` 0.7 | 480 | 9 | 28 / 34 / 120 |
| `top_p` 0.9 | 480 | 9 | 28 / 36 / 120 |
| `presence_penalty` 0.5 | 480 | 22 | 29 / 88 / 120 |

- **崩れは「名前を書き終えたあと閉じずに言い換えを続ける」もので、冒頭は使える名前になっている。**読めなかった 10 件は、最初の「,」か「 or 」までがどれも名前として読めた (人が見た、答えは証拠に入れていない)。
  読めた答えの英名は中央値 57 文字、95% 点 85 文字。
- `maxLength` は llama.cpp が文法に変えるので、閉じ引用符が強制される。**本線の英名のスキーマに 1 行足せば済む** (kajimachine は変えていない)。
- 同じ 80 個版・同じ 96 枚の「なし」が、48 の 3090 では 17 / 480、ここでは 10 / 480。**480 回の崩れの数は 7 件ぶれる。**48 §5 の 96・80・64 個の順が言えないのと同じ。
- 繰り返しの罰則が増やすのは、閉じるのに要る引用符や括弧も罰するからだと読める (導出、未確認)。

## 4. やっていないこと

- 鑑定機の画面を実際に動かしながらの M6 の再生と、長時間の運転。
- M6 の鑑定用サーバーの載せ替え (TsugumiServer → llama-server)。jenga の `experiments/m6_vlm/m6_restart.sh` は TsugumiServer を起こす形のまま。
- 本線のスキーマへの `maxLength` の追加。読み・選択・動作の文字列には試していない (これらは 48 の 192 回 × 各腕で 80 個の読めない答えが 0)。
- 88 個 (9.51 GiB) や 96 個をログインした状態で載せること。
