# 02. 証拠の規則 — でっちあげを構造で防ぐ

LLM は Apple silicon の仕様を**もっともらしく捏造する**。この repo でも起きた (§3)。
対策は「注意する」ではなく、**証拠ディレクトリ無しでは数字を書けない形にする**こと。

## 1. 札

| 札 | 意味 | 要件 |
| --- | --- | --- |
| **実測** | 手元で数字を取った | **`bench/m6/results/` の証拠ディレクトリへのリンクが必須** |
| **導出** | 実測または公称から計算した | 元の実測 (リンク) と式を併記 |
| **公称** | Apple / 論文 / 報道の記載 | 出典 URL。手元で取っていないと書く |
| **未確認** | 根拠を持っていない | 断定しない。台帳 ([03](03-FACTS.md)) には「未確認」列で載せる |

## 2. 証拠ディレクトリ

`bench/m6/results/YYYY-MM-DD-<hw.model>-<label>/` (`Mac15-6` = MBP、`Mac18-5` = M6)。スクリプトが自動で作る。

| ファイル | 中身 | 作る側 |
| --- | --- | --- |
| `hostinfo.txt` | `bench/hostinfo.sh` の 1 行 (機種 / OS / Swift / SDK / SSD / **commit** / minos) | 自動 |
| `command.txt` | 実行した完全なコマンド | 自動 |
| `env.txt` | `TF_*` の環境変数 (A/B の腕の証明) | 自動 |
| `run-N.log` | 生の stdout + stderr。**削らない** | 自動 |
| `run-N.pre.txt` | 実行直前の `vm_stat` / `memory_pressure` (16 GB 機のページキャッシュ条件) | 自動 |
| `summary.tsv` | footer から抜いた表。文書はここから中央値を引く | 自動 |
| `output.txt` | 単発プローブの出力 | 自動 |

- 解釈を書くセルは **n ≥ 3**。中央値とレンジを書く。外れ値は捨てずに残して `pre.txt` で説明する。
- 証拠ディレクトリは結果文書と同じ commit に入れる。
- 文書からのリンクは相対パスで `../../bench/m6/results/<dir>/summary.tsv` の形。

## 3. この repo で実際に起きた例 — 何が信じられ、何が外れたか

| 主張 (出所) | 実際 | 教訓 |
| --- | --- | --- |
| 「SSD は前世代比 2 倍」(Apple 公称) | 256 GB 構成は **3.34 GB/s、M3 Pro 1 TB の半分** ([M6_SSD_BANDWIDTH](../investigations/M6_SSD_BANDWIDTH.md)) | 公称の「2 倍」は比較対象の構成を言っていない |
| 「ANE は GPU の 2 倍出る」(M3 Pro の実測を M6 に持ち込んだ) | M6 の GPU は fp16 GEMM で **18.61 TFLOP/s** ([証拠](../../bench/m6/results/2026-09-22-Mac18-5-gpu_peak_probe/output.txt))、比は逆転 | **別機の比を家族の外に持ち出さない** |
| 「M5 は apple9 を名乗り feature flag で引けない」(報道、未確認のまま載った) | M6 は apple10 / apple11 / metal4 **すべて true** ([証拠](../../bench/m6/results/2026-09-22-Mac18-5-gpu_family_probe/output.txt)) | family は `MTLDevice` に聞く。記事に聞かない |
| 「macOS 27 なら tensor 経路が自動で生き返る」(コードを読んだ導出) | PSO は作れるが、**ベンチのモデルが group 32 なので `MPPPrefillInt4QMM` は init で nil**。機械ではなくモデルの問題だった | コードを読んだだけの「動くはず」は実測ではない |
| 「12 コアなので tensor 無しでは遅くなるかもしれない」(導出) | 1.22 倍**速かった** (旧文書 §7-4a。ただし証拠ディレクトリ無し → G0-3 で取り直す) | 悲観も楽観も測るまで書かない |
| 「`matmul2d` が Neural Accelerator を叩く唯一の経路」(公称) | **まだ何も測っていない。**G2 がこれ | 本命の前提が未検証のまま設計に入っていた |

## 4. LLM への禁止事項 (この文書群を書くとき)

1. コア数・帯域・family・命令セット・SSD 速度を**記憶から書かない**。`sysctl` / `MTLDevice` / プローブの出力から引く。
2. 「N 倍」は**同一機・同一 commit・同一コマンドの対**でしか書かない。機械をまたぐ比は「世代差」と「実装差」が混ざるので、書くなら両方の証拠を並べる。
3. 別機・別プロジェクトの数字を M6 の期待値にしない。
4. 単体ベンチの勝ちは**本番ループで確かめるまで勝ちではない** ([05 §2](05-RISKS.md))。
5. 証拠ディレクトリの無い数字を見つけたら、消すか「証拠なし」の札を付ける。旧文書の数字を新文書に写すときも同じ。
6. 計測の前に「期待値」を書くなら**導出**と明記し、式と元の実測を付ける。合否の閾値は計測前に [04](04-GATES.md) に置く (後から動かさない)。
