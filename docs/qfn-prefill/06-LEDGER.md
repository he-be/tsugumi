**この文書の表は `bench/qfn/ledger.sh` の出力を貼ったもので、手で行を書かない。**
prefill について「速くなった」と言うときは、必ず §1 の行を指す。指せない主張は進捗ではない。

## 0. 規則

1. **測る量は 2 つ、列は 2 つ。**
   - 本文 1: 自然文 5 本 (`bench/m6/prompts/`) を 1 本ずつ新しいプロセスで。行は本文ごとの中央値 (秒)。
   - 本文 2: 記録の再生 1 ターン (ToolLoopCheck の replay、結果文書に記録名を書く)。行は 1 ターンの prefill 合計 (秒) と、ラウンドごとの中央値。
   - 列: **単体** (MBP だけ) と **2 機** (MBP + M6、既定の分け方と k / σ)。同じ commit・同じ本文・同じスクリプト。
2. 既定のバイナリ (`Q38_` / `TF_` なし、追加引数なし)、運用点 (32K / KV Q8_0 / チャンク 2048 / thinking off)。ラベルは `ledger-<何>`。
   `pair_bench.sh` は `ledger-*` に環境変数か追加引数が付いていると測らずに止まる。
3. **比の列は無い。**倍率・%・tok/s は、この文書にも README の現在地にも書かない。変更の効果は秒の差で書く。
4. **行が増えるのは証拠ディレクトリができたときだけ。**同じ commit で n ≥ 6。表は `ledger.sh` で作り直して貼る (§2 は `--all`)。
5. 行には 1 run の読み (MBP 内蔵 / M6 内蔵 / M6 外付け の MB) と、2 機の行には分け方 (A k / B σ) と link の待ちを添える。
6. `Q38_` 付きの構成は候補であって進捗ではない (§2)。検査を通って秒が縮んだ候補は既定に入れる ([04](04-GATES.md))。
