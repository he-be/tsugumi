# 04. Gate — 問い・測り方・合否

各 Gate は **証拠ディレクトリと結果文書が揃って初めて閉じる**。合否の閾値はここに先に置き、計測後に動かさない。
原則は [m6-prefill/04](../m6-prefill/04-GATES.md) の 5 つと同じ (進捗は台帳の秒だけ / `Q38_` 付きは候補 / 測る量を混ぜない / 正しさを付ける)。

## Q0. 基準線 — 今のコードの単体を `bench/qfn/` の形で取る

- **作るもの**: `bench/qfn/pair_bench.sh` (単体と 2 機を同じ形で)、`bench/qfn/ledger.sh`、`bench/qfn/results/README.md`。本文は 2 種類。
  - 本文 1: `bench/m6/prompts/` の自然文 5 本、1 本ずつ新しいプロセスで ((c)、run ごとに本文を替える)。
  - 本文 2: 記録の再生 1 ターン (`TsugumiToolLoopCheck` の replay、Offline の 1 問、ラウンド 3〜7)。同じプロセスで複数ラウンド ((b))。
    使う記録は結果文書に名前を書く (qwen38/43 の `RoundMeter` の形)。
- **測り方**: MBP 単体、既定 (`Q38_` なし)、32K / KV Q8_0 / チャンク 2048。`Q38_ROUND_LOG` は別の run で on にして段の秒を取る。n = 6。
- **合格**: 台帳に単体の行が 2 つ (本文 1 の 5 本の中央値、本文 2 の 1 ターンの prefill 合計)。同じ commit で 6 本の中央値の揺れの幅 (最大 − 最小) が結果文書にある。
  **以降の Gate の「縮んだ」の閾値は、この揺れの幅の 2 倍を下回らない秒に置く。**

## Q1. 分け方を決める実験 ([07](07-EXPERIMENTS.md))

- **前提**: [12 §1](12-Q1-REDESIGN.md) の P1〜P5 (M6 は fp16 の tensor ops、担当分の常駐と wired limit は M6 で可、物差しは本文 2、Q2 を先、式は格子を絞るだけ)。**Q0 と Q2 が先。**
- **やること**: E0〜E2 (済み、[10](10-Q1-SPLIT-DECISION.md)) に加え、F1 (M6 の 1 層を tensor ops で、冷 / 常駐)、F2 (A の模擬)、F3 (B の模擬、tensor ops と常駐)、F4 (常駐の上限)。各 n ≥ 3。
- **決め方**: [12 §3](12-Q1-REDESIGN.md) のとおり。F2・F3 の模擬の壁時計に記録のラウンド分布を掛けた 1 ターンの prefill 合計秒で A か B を選ぶ。差が Q0 の揺れの幅の 2 倍未満なら B。**式では選ばない。**
- **合格**: F0〜F4 の証拠ディレクトリと、結果 (A か B、k か σ、常駐の上限、P1 の経路と精度) を書いた結果文書がある。**この Gate を閉じるまで Q6 のコードを書かない。**
- **途中で止める条件**: E1 で M6 が 4K の 1 チャンクを Swapouts なしで通した (10 §0-2) ので A は残る。F2 で M6 側が k 層の常駐で Swapouts を出すなら、その k は落とす。

## Q2. PLE の行を先に読む (分け方に依らない)

- **作るもの**: 要求の頭で全チャンクの行番号を出し、並列に pread。候補は `Q38_PLE_PREFETCH=1`。
- **測り方**: 本文 2 (再生 1 ターン) の `Q38_ROUND_LOG` の `ple` の秒。単体。加えて、冷えた 1 チャンク (本文 1)。
- **合格**: `ple` が 1 チャンクあたり 0.5 s を下回る (今は冷えて 2.5〜5.4 s、R2 で 3.15 s)。壁時計が Q0 の閾値以上縮む。既定に入れる。

## Q3. host の top-10 (分け方に依らない)

- **作るもの**: GPU の top-10 か、host の SIMD 化。候補は `Q38_TOPK=gpu|simd`。
- **測り方**: `Q38_ROUND_LOG` の `routeTopK` (チャンク 2048 で今 約 1.3 s)。
- **合格**: `routeTopK` が 1 チャンク 0.2 s を下回り、選ばれた expert と重みが host 版と一致 (KernelCheck に足す)。壁時計が閾値以上縮む。既定に入れる。

## Q4. M6 の第二の読み口 (分け方に依らない。A では非常駐層の読み)

- **腕 a: 外付けに expert の写し。**前提は E2 (内蔵 / 外付け / 同時)。作るものは expert のバイト範囲の写し (`Scripts/qwen38/make_expert_mirror.sh`)、`preadRanges` の 2 本目の fd、share。候補は `Q38_EXPERT_MIRROR=<dir>`。
- **腕 b: MBP の内蔵 SSD から TB4 で送る** ([19 §2](19-AFTER-Q1-PLAN.md))。M6 が選ばれた expert の一覧を送り、MBP が担当分を `pread` して link で返す。受け口は 17 の固定の置き場。候補は `Q38_EXPERT_FEED=<比>`。**先に M6 の 3 つの TB ポートが対称かを、link と外付けの同時転送で確かめる** (19 §2-3-1)。
- **測り方**: まず `--qfn-pair-sim` の A k 40 常駐で腕ごとに n = 3 (19 §2-4)。本番の層では M6 側の run で腕なし / a / b をまとめて (block) n = 4。`iostat` の disk ごとの MB と link の GB/s を添える。
- **合格**: 5 本とも縮む向きが揃い、M6 側の秒が閾値以上縮む。Pageins は増えない。両機 Swapouts 0。既定に入れ、腕 a は `expert-mirror.json` と同じ運用 (未マウントなら警告)、腕 b は link が無ければ内蔵だけに戻る。

## Q5. 機内で読みと GPU を重ねる (M6 側は Q6 の前に模擬で、MBP 側は判断待ち)

- **前提**: MBP 側はユーザーの判断 (README の判断待ち 3)。M6 側は判断待ちに入っていない (常駐と wired limit は P2 で決まった)。
  送りありの k 48 では M6 のチャンクは読み 2.93 s + 計算 3.28 s の直列で、読みの方が短い ([20 §3](20-Q4B-EXPERT-FEED.md))。19 §1-2 の「M6 側は隠れない」は送りの前の値で、もう当てはまらない。
- **作るもの**: 2 層分の固定の置き場 (`F_NOCACHE` の pread、`MTLBuffer`)、層 L+1 の全 expert を層 L の裏で読む。候補は `Q38_EXPERT_SLAB=2`。
  M6 側は先に `--qfn-pair-sim` の staging を 2 層分にして、層 L の GPU の間に層 L+1 の読み (内蔵 + 送り) を走らせる。
- **測り方 (M6 側、模擬)**: `f23_pair.sh` の形で k 48・比 0.59、staging 1 層分 (20 の値) と 2 層分を交互に n = 3。常駐 13 層で Swapouts が出れば常駐 12 層も取る。M6 の `vm_stat` の Swapouts、wired の最大と free。
- **測り方 (本番)**: 本文 1・本文 2。両機の `vm_stat` の Swapouts、wired の最大 (`Q38_MEM_LOG`)。
- **合格**: **Swapouts 0** (両機)、wired の最大が `recommendedMaxWorkingSetSize` を超えない、壁時計が閾値以上縮む (模擬は M6 のチャンクで 3.06 s 以上)。1 つでも外れたら既定に入れず、候補のまま残す。
  模擬の見込みはチャンク 6.30 → 約 3.4 s (導出)。実測が見込みと 1 割以上ずれたら、読みと計算のどちらがずれたかを書く。
- **結果 (M6 側、模擬)**: **A に入れる** ([21](21-Q5-M6-OVERLAP.md)、ユーザーの判断)。M6 のチャンク 6.301 → 3.829 s で差は閾値に届かないが、t1・t2・1 ターンとも縮む。RAM (Swapouts 0、wired ≤ 14336 MiB) は通った。見込みとのずれは読みの側 (非常駐層は 1 層ごとに読み > 計算)。

## Q6. 選んだ分け方を作る — 正しさと秒

- **作るもの**: Q1 で選んだ方 ([08 §1 か §2](08-CANDIDATES.md))。link は `bridge0` の生 TCP、link-local にだけ bind。
- **正しさ**: 同じプロンプト (本文 1 の 1 本) で、単体の logits と 2 機の logits の差 (最大絶対値と top-1 の一致)。合格の幅は**計測前に置く**: M6 は fp16 の tensor ops を使うのでビット一致しない ([11 §1](11-Q1-REOPEN-TENSOR-OPS.md))。ds4-metal の Q2 と同じく、カーネル単体は腕 A との差 ≤ 2e-3 × scale、モデルは top-1 の一致率と logits の差の分布を記録し、入れ替わった位置がすべて相手の top-5 に入ること。greedy 64 トークンの本文を記録する (違っても止めない)。
- **前提 P6 (設計で先に書く、[20 §3](20-Q4B-EXPERT-FEED.md))**: decode の k と、prefill 後の層の状態の置き場。A では M6 が層 0〜k−1 の状態を持ち、decode は 2 ホップ (08 §1)。
  k 48 のままだと decode も M6 が全層を回して 35 層分の expert を毎トークン流す。prefill と decode で k を変えるなら、prefill 後に層 13〜k−1 の状態 (attention 層の KV、GDN の状態と conv 履歴) を MBP に送る仕組みが要る。
  どちらにするかは Q7 の合格 (decode の 1 ステップ中央値が単体より遅くない) で決める。決める前に測る量: M6 の decode 1 ステップ (常駐 13 層 + 流す層、模擬)、送る状態の大きさと link 4.7 GB/s での秒 (導出)。この前提が書けるまで k の格子は測らない。
  **→ 下書き ([22](22-Q6-P6-DECODE-PLACEMENT.md)): decode は MBP、M6 は状態を受け渡す。M6 の全層 decode は今のコード・MTP off で 207 ms 対 MBP 192 ms。運用点 (MTP on) と層で分けた decode は未測定で、[23](23-DECODE-SPLIT-PLAN.md) (s/token、S0 / S16 / S24 / S32 / S48) で判別してから確定する。**
- **k**: Q1 の模擬 (F2、Q4 の腕 b を採用ならその条件) で最小だった値から始め、その前後 2 点を n = 3 ずつ測り、壁時計の中央値が最小のものを既定にする (聞かない)。送り 比 0.59 の模擬では 48 が最小で、格子は 44・46・48 ([20 §1.5](20-Q4B-EXPERT-FEED.md))。
  1 チャンクと 2 チャンク以上で最小の k が違い、切り替えた 1 ターンの合計が 1 つの k より閾値以上短ければ、チャンク数で k を切り替える ([19 §1-3](19-AFTER-Q1-PLAN.md))。模擬では t2 が k 40〜48 で 0.3 s 以内に揃い、切り替えは閾値に届かないので、本番も 1 つの k から始める。常駐 13 層 (層 0〜12) は k に依らない。
- **合格**: 正しさが幅に入る。本文 1・本文 2 とも、単体の行より Q0 の閾値以上縮む。Swapouts は両機とも 0。**式の予測と実測が 1 割以上ずれたら、結果文書にどの量がずれたかを書く。**
- **不合格なら**: link の待ちが壁時計の 1 割を超えていれば E0 / E3 の前提が違う。M6 側の秒が式より大きければ E1 / E4 の値が本番ループで再現していない (m6-prefill/05 §2)。

## Q7. decode と会話の機能 (2 機)

- **測り方**: 本文 2 の再生 1 ターンの decode の合計秒と 1 ステップの中央値 (MTP on/off)。`Tests/TsugumiServer/Qwen38PromptCacheTests` と ToolLoopCheck の Offline 5 問が 2 機で通る。
  A ならチェックポイントの取得 / 復元 / 捨てが両機で同じ id で動く (ログ)。B なら decode は単体と同じ経路で、M6 を decode に使う腕は候補として別に測る。
- **合格**: 2 機の decode の 1 ステップ中央値が単体より遅くない (差 ≤ Q0 の揺れの幅)。テストが緑。MTP の受理率が単体と同じ幅 (0.77〜0.97、[qwen38/10](../qwen38/10-MTP-SHADOW-SPEC.md))。

## Q8. 小さいラウンドの固定分

- **問い**: 回帰の切片 6.2 s と、8 トークンのチャンク 2.5〜2.7 s ([03 §3](03-FACTS.md)) はどこか。`Q38_PREAD_MIN_T` (32) 未満のチャンクは advise とフォルトで読まれる。
- **測り方**: 本文 2 のラウンドを新規トークン数で分け (0〜31 / 32〜255 / 256〜2047)、`Q38_ROUND_LOG` の段の秒。
- **合格**: 切片が 3 s を下回る。閾値は Q0 の後、切片の実測を見てから置き直してよい (この Gate だけ、Q0 の前には置けない)。

## Gate の間で共通

- 正しさ: 変更のたびに KernelCheck (`Qwen38*`) と greedy 64 の記録。
- **既定に入れる条件** (B3 と同じ): 検査を通り、同じバイナリで既定と交互に取った壁時計が閾値以上縮んだ候補は、聞かずに既定に入れる。既定に入れたら `ledger-*` の行で確かめる。
- 運用点 (32K、KV Q8_0、チャンク 2048、サンプリング) は動かさない。
