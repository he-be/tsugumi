# 08. 2 機の分け方の候補 — A 層で分ける / B expert で分ける

どちらも「MBP 単体で動き、M6 を TB4 で直結すると速くなる」を満たす。**どちらを作るかは [07](07-EXPERIMENTS.md) の実験の後に式で決める。**
ここには形と式だけを書き、数字は書かない (今ある数字は全部 MBP 単体の実測で、M6 と link の数字は無い)。

## 1. A — 層で分ける (M6 が層 0〜k−1 と PLE、MBP が層 k〜47 と head)

- M6 は embedding → PLE (層 1) → 層 0〜k−1 を回し、残差 (T × 4 × 2560 fp32 = T = 2048 で 84 MB) をチャンク単位で MBP に送る。MBP は層 k〜47 → head → MTP → サンプラ。
- **M6 が状態を持つ**: 層 0〜k−1 の GDN 状態・KV・PLE 履歴・チェックポイント。チェックポイントは両機が同じ id で取る・戻す・捨てる。prompt cache の場面表は MBP。
- decode も 1 トークンごとに MBP → M6 → MBP の 2 ホップ。
- チャンクが 2 つ以上あれば、MBP がチャンク c の後半を回す間に M6 が c+1 の前半を回す (重なる)。**1 チャンクのラウンド (アプリの 8 割) では重ならず、2 機の秒の和になる。**
- 要るもの: M6 側のプロセス (`Qwen38Runner` を層の範囲で開く)、link、チェックポイントの同期、M6 に PLE BF16 (置いた、[03 §5](03-FACTS.md))。
- llama.cpp の `-sm layer` と同じ形。

## 2. B — expert で分ける (M6 は状態を持たない expert 計算機)

- MBP が単体と同じく全部を持つ (embedding、PLE、dense、router、head、MTP、KV、GDN 状態、チェックポイント、prompt cache)。
- 層ごとに、MBP が router の入力 `mixed` (T × 2560 fp32 = 21 MB) と top-10 の割り当て (T × 10 × 8 B) を M6 に送る。M6 は担当分 σ (0 < σ < 1、expert 番号で決める) の expert を読んで GEMM し、部分和 (21 MB) を返す。MBP は残り (1 − σ) を自分で計算して足す。
- **M6 に状態が無い。**重みは expert のバイト範囲だけ (PLE・dense・KV は要らない)。落ちたら MBP が全部やる (単体) に戻れる。
- decode は単体のまま (M6 を使うかは別の Gate で測る)。1 チャンクのラウンドでも両機が同じ層で同時に働く。
- 代償: **層ごとに往復 (42 MB) が 48 回**。link の同期が 48 回。MBP の dense と top-10 は分かれない。
- 要るもの: expert 計算プロセス、link、`moeRouted` の分岐 (担当分だけ GPU に流し、残りを link へ)。
- llama.cpp の `-sm row` に近いが、dense は複製せず MBP だけが持つ。

## 3. 式 (E0〜E4 の量を入れる。1 チャンク T = 2048、48 層)

記号 ([07](07-EXPERIMENTS.md) で測る): d_X = dense (pre-router) の GPU 秒/層、r_X = 1 層の全 expert の routed GPU 秒、s_X = 1 層の expert を読む秒 (M6 は写しあり s_M6+ も)、
t_X = top-10 秒/層、p_X = PLE 秒/チャンク、l_1 = 84 MB 片道の秒、l_48 = 21 MB 往復 × 48 の秒。X ∈ {MBP, M6}。
機内は今と同じく読み → GPU が直列 (Q5 が通れば s + r → max(s, r) に置き換える)。

| | 1 チャンクのラウンド | 2 チャンク以上の定常 (チャンクあたり) |
| --- | --- | --- |
| 単体 | 48 (d_MBP + t_MBP + s_MBP + r_MBP) + p_MBP | 同左 |
| **A** (k 層を M6) | k (d_M6 + t_M6 + s_M6 + r_M6) + (48 − k)(d_MBP + t_MBP + s_MBP + r_MBP) + p_M6 + l_1 | max( k (d_M6 + t_M6 + s_M6 + r_M6) + p_M6, (48 − k)(d_MBP + t_MBP + s_MBP + r_MBP) ) + l_1 |
| **B** (担当 σ を M6) | 48 [ d_MBP + t_MBP + max( (1 − σ)(s_MBP + r_MBP), σ (s_M6 + r_M6) + l_48 / 48 ) ] + p_MBP | 同左 |

- A の k と B の σ は、それぞれ式が最小になる値を選ぶ (k は整数、σ は 0.05 刻み)。
- E4-(b) が縮んでいれば r_M6 を r_M6,nax に置き換えた行も出す。
- 記録の 1 ターンは、ラウンドごとの新規トークン数からチャンク数を出し (2048 で切り上げ)、上の式を足す。固定分 (6.2 s の切片、[03 §3](03-FACTS.md)) は A・B に共通なので比較には入れない (Q7 で別に扱う)。

## 4. 両方に共通で、設計に依らないもの

| Gate | 中身 | どちらでも効く理由 |
| --- | --- | --- |
| Q2 PLE の行の先読み | 行番号はトークン列だけで決まる | A では M6 の外付け、B では MBP の内蔵。どちらでも host の直列を外す |
| Q3 host の top-10 | GPU で出すか SIMD 化 | A では両機、B では MBP |
| Q4 M6 の外付けに expert の写し | 内蔵 + 外付けを同時に読む | A では層 0〜k−1、B では担当分。E2 で先に写しを作る |
| Q5 機内で読みと GPU を重ねる | 固定の置き場 2 層分 | 両方の式の s + r を max(s, r) にする。RAM の判断待ち |

## 5. 両方でやらないこと

- dense を 2 機で分ける (attention のヘッド分割、GDN の分割)。往復が層ごとに 2 回になり、状態が両機に散る。
- M6 単体の運用。途中で落ちた M6 の状態を MBP に持ち込んで続けること (A)。
- チャンク幅・スロット・文脈長・サンプリングの変更。挙動の評価。
