## 0. 結論

1. **M6 の TB ポートは 3 つとも別のバス**で、link と外付けを同時に流しても落ちない (§1.1)。ケーブルの差し替え (19 §2-3-1 の 3 通り) はしていない。
2. **腕 b は 19 §2-4 の合否のうち M6 側と壁時計の条件を通る (比 0.59)。**M6 のチャンクは 8.281 / 8.135 → 5.139 / 5.022 s (チャンク 0 / 1、差 3.142 / 3.113 s、閾値 3.06 s)、
   t1 10.376 → 7.978 s、t2 18.509 → 12.916 s。記録の 1 ターン (18 と同じ配分、導出) は 835.7 → 621.5 s。比 0.5 は M6 のチャンクの差が 2.72 s で閾値に届かない。
3. **MBP の Pageins は 1 run +0.02〜0.11 → +13.09〜14.52 GB に増えた。**中身は送りの読み (20.4 GB、F_NOCACHE。どれだけ Pageins に数えられるかは分けていない) と、ページキャッシュに残らなくなった MBP の自分の 8 層 (層 40〜47)
   (読み 0.21〜0.25 → 0.70〜0.85 s / チャンク)。この秒は t1・t2 に入っている。M6 の Pageins は 17.74 → 9.39 GB に減った。
4. **送り (比 0.59) の下で k を 32〜48 と動かすと、1 ターン (導出) は k が大きいほど短く、k 48 が最小で 529.9 s** (k 44 563.5 / 569.4 s、k 46 553.2 s)。
   k 48 は M6 が 48 層を全部回し、MBP は層を持たず送るだけの形。t2 は k 40〜48 で 12.56〜12.86 s でほぼ動かず、t1 が 8.133 → 6.321 s と縮む (§1.5)。格子の端は設計の端 (k ≤ 48) で、この先は無い。

## 2. 分かったこと / 外れたこと

- 19 §2-4 の合否: **比 0.59 は M6 のチャンクが閾値以上縮み (3.113〜3.142 s)、t1・t2 とも縮み、Swapouts 0。**M6 の Pageins は減った。
  **MBP の Pageins は増えた。**04 Q4 の「Pageins は増えない」は読み側 (M6) のページキャッシュを想定した条件で、MBP の増分の秒 (自分の 8 層を毎回読む分) は t1・t2 に入ったうえで縮んでいる。
  18 §2 は「MBP が毎回読むとすると t1・t2 に約 0.6 s 足される」と書いていて、実際の運用 (プロンプトごとに route が違う) はこちらに近い。目的の指標 (壁時計) で判定し、比 0.59 を Q6 の A に入れる。
- 19 §2-2 の見込み (導出): 読み口 約 8.1 GB/s、M6 のチャンク 5.7〜6.3 s。実測は 7.58〜7.60 GB/s、5.02〜5.15 s。チャンクが見込みより短いのは、18 の読みが 1 チャンク約 5.3 s で見込みの前提 (4.1〜6.2 s) の中ほどだったため。
- 比 0.5 と 0.59 の差は、2 つの口の帯域比 (3.34 : 4.73、0.59) で揃えると遅い方の口が消えることで説明できる。0.59 は 3 点目を測っていない (比 0.65 など)。
- 測っていない: `iostat` の disk ごとの MB (19 §2-4 が挙げた量)。M6 の内蔵の MB はログの piece の和、MBP の送りの MB は `feed` 行から出した。

- **送りがあると、模擬では M6 に全層を任せる形 (k 48) が最小になった。**M6 の 1 層 (tensor ops、常駐 13 層 + 流す層) が MBP の 1 層より短く、
  送りで M6 の読みが縮んだため、MBP に層を残す理由が 1 チャンクのラウンドでは無くなった。2 チャンク以上では t2 が k 40〜48 で動かない (M6 の段が律速)。
- 模擬に入っていないもの: attention / GDN の中身・norm・要素ごとの仕事・PLE・head (18 §2)。MBP では模擬の単体 1 チャンク 16.26 s が E1 の 20.07 s より短い (18 §2)。
  M6 の tensor ops の経路で同じ差は測っていない (E1 の M6 は fp32 の今のコード)。k 48 の優位は、この仕事が M6 で MBP よりどれだけ長いかで縮む。

## 3. 次の Gate に渡すもの

- **Q6 の k の出発点は 48 (送り 比 0.59)。**04 Q6 の規則 (模擬の最小から始め前後 2 点) では 44・46・48。k 48 は MBP が prefill の層を持たない形で、
  MBP の仕事は送り・LM head・サンプラ・decode になる。t2 は k 40〜48 で揃うので、19 §1-3 の「チャンク数で k を切り替える」は閾値に届かない (導出、2 チャンクの差 0.3 s 以内)。
- MBP の自分の層の読みが毎回になった分 (0.5〜0.6 s / チャンク) は、本番の層でも出る。Q5 (機内で読みと GPU を重ねる、MBP 側は判断待ち 3) の対象。
- 候補の名前は `Q38_EXPERT_FEED=<比>` (04 Q4)。既定に入れるのは Q6 の本番の層で縮んだとき。link が無ければ内蔵だけに戻る。
- 開いたまま: 比 0.59 より上の点、3 口 (内蔵 + 外付け + TB4、19 §2-4 の最後)、送りを要求より先に始める (M6 は route が分かった時点で次の層を頼める)。
