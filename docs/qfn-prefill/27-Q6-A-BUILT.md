## 2. 分かったこと / 外れたこと

1. **受け渡しは正しい。**同じ MBP の中で serve を立てた run は 17 行すべて差 0。M6 との差は GPU の違い (P1 なしの M6 でも相対差の中央値 5e-2、P1 で 9e-2、prompt-code 2,500 トークン)。
   この項の数字は開発中の run で、証拠ディレクトリは無い (未確認)。
2. **常駐は 13 層に入らなかった (22 §2-3 の懸念どおり)。**runner の作業領域 2.9 GB (チャンク分の固定バッファ 1.47、KV 32K 分 0.55、ほか) が模擬に無く、13 層・12 層は round 中に wired 16.0 / 15.2 GB でスワップした (開発中の run、証拠ディレクトリなし)。10 層で wired 最大 13.51〜13.58 GB。
   固定バッファのうち PLE の層だけで使う 5 本 (0.42 GB) を他と共有すれば 1 層分近く空く (未着手)。
3. **非常駐層は丸ごと読む。**模擬は層ごとの選ばれた expert をルートの記録から先に知っていたが、本番は層のルーターまで分からない。2,048 トークンで層あたり 286〜470 / 512 (中央値 402) が選ばれ (F2 の記録)、丸ごとは約 +27%。
   末尾の短いチャンク (268〜452 トークン) でも同じ 29 GB を読み、M6 は約 4.1 s 待つ。
4. **模擬 (21) の M6 のチャンク 3.829 s から外れた (8.576 s)。**GPU が 3.28 → 4.67 s (注意・GDN・norm などの o_X が入った)、PLE 1.16 s (外付け)、置き場の待ち 3.53 s (丸ごと読み + 常駐 10 層)。
5. M6 の `advise` は 0.001 s (置き場の層は読まない)。26 §3 の「層ごとの `advise` を単体と並べる」は、本番の M6 が advise しないので当たらない。
6. 計画からのずれ: (a) 正しさの本文は ja-twomachine のみ。(b) `q6-check` の最初の試みは MBP の送り手が EINTR で抜けて止まった (7241594 より前、証拠は捨てた)。EINTR / EAGAIN の再試行を入れて取り直した。
   (c) `serve.m6.log` / `serve.m6.guard.txt` は `QFN_APPEND` の回ごとに上書きされ、最後の巡の分だけ残る (M6 の Swapouts は run ごとの `*.m6.txt` にある)。(d) 試走の本文 2 は MBP の送り手の正常な終わりを失敗と数えて exit 8 (576dfd7 で直した)。
   (e) 04 Q6 の「Swapouts は両機とも 0」は MBP で外れた (上の和)。有効条件は 2026-09-25 のユーザーの判断で「guard が止めていない・exit 0」(24)。
