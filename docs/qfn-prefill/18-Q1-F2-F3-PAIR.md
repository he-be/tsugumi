## 0. 結論

1. **12 §3 の決め方で A。**記録のラウンド分布 (1 チャンク 55 本、2 チャンク 10 本、3 チャンク 3 本) に模擬の壁時計を掛けた 1 ターンの prefill 合計 (導出) は、
   常駐の条件で **A 837.5 s (k 40) 対 B 978.3 s (σ 0.55)**、差 140.8 s。閾値 3.06 s (13) を上回る。
   冷えた条件では B 1067.5 s (σ 0.40) が A 1099.2 s (k 34) より 31.7 s 短いが、A は常駐の条件で速くなる分け方で、12 §3-3 (冷えた条件でしか速くならない分け方は選ばない) には当たらない。
2. **A の最小 (k 40) と B の冷の最小 (σ 0.40) は格子の端。**k 40 より上、σ 0.40 より下は測っていない。
3. B は σ を動かしても 1 チャンクが 11.57〜11.70 s (常駐) で止まる。MBP に残る dense の GPU 約 3.5 s と読み 2.4〜3.2 s が 1 チャンクにあり、M6 に渡せるのは routed だけ (§1.3)。

## 2. 分かったこと / 外れたこと

- **式 (格子を絞った式) は全条件で模擬より短く、A・B の条件で差は 23.5〜193.2 s/ターン** (B σ 0.45 常駐が最小、B σ 0.50 冷が最大。単体は 16.5 s)。式の最小の位置も外れた: A 常駐は式 k 32 / 模擬 k 40、B 冷は式 σ 0.50 / 模擬 σ 0.40。12 §3-4 のとおり式は直さない。
  式に入れていない秒は M6 の層の最初のカーネル組み立て (層 0 で 0.21 s)、B の M6 が受け取ってから読む直列、ソケットの受け渡し (§1.3 の M6 の recv / send は 2 チャンクで 1.6〜1.7 s)。
- **A k 40 の MBP の 8 層は同じ route の繰り返しでページキャッシュに残った** (1 run の Pageins 0.01 GB)。MBP が毎回読むとすると t1・t2 に約 0.6 s 足され (他の条件の MBP の 1 層の読み 0.1 s × 8 層 − 0.24 s、導出)、1 ターンは約 880 s (導出) で B 978.3 s より短いまま。
- 模擬に入っていない仕事: 注意と GDN の中身、norm、要素ごとの演算、PLE、head。MBP 単体の模擬は 1 チャンク 16.26 s で、E1 の MBP の 2 本目のチャンク 20.07 s (10 §1.2、PLE の先読みの前) より短い。
- MBP 側は今のコード (routed は T ≥ 1024 の `routedGemm`、24 ペア未満の expert は per-pair)。E3 (10) の腕 B (全部 sgemm) より 1 層の routed が短い (0.11〜0.16 s)。
- M6 の読みと GPU は重ねていない (層ごとに読み → GPU)。
- 計画からのずれ:
  1. F2・F3 を 1 本の道具 (`--qfn-pair-sim`) にし、B でも MBP が dense を回す (12 の F3 は E3 の取り直しで routed だけ)。A と B で MBP の仕事を揃えるため。
  2. 常駐の量は担当の範囲の expert 全部で数えた (17 は選ばれた分で数えた)。別のプロンプトは別の expert を選ぶので。A の常駐は 17 の 17 層ではなく 13 層。
  3. k / σ の格子は、測定の前に 1 回流した MBP 単体の模擬 (`grid-input-solo.log`) と F1・F4 の値から式で出した (`bench/qfn/f23_grid.py`)。
  4. 試走で、M6 のログに前の run の `listening` が残っていて MBP が早く接続し、B の 1 本が止まった (`f23-trial`)。M6 側を自分で止め、ログの削除を起動の前に移した。
  5. 分割と自前のバッファの検査 (`QFN_SIM_CHECK=1`): 層 0 の routed を全体 = [0, 256) + [256, 512) で、MBP 7.34e-08、M6 (上半分は自前のバッファ) 9.47e-08 (証拠なし、端末の出力)。

## 3. 次の Gate に渡すもの

- **Q6 で作るのは A** (M6 が層 0〜k−1、常駐 13 層)。k は格子の端の 40 で、それより上は未測定。
- A では M6 が層 0〜k−1 の KV と再帰の状態を持つ。decode と prompt cache に手が入る (12 §3-2 で差が小さければ B を選ぶ理由にした点)。M6 の PLE (README の判断待ち 4) も A では要る。
