# 16. 2 候補の品質差と `in_proj_a` の実活性再測 (実測(手元)、2026-08-21)

[04-PHASES.md](04-PHASES.md)「次の一手」8 と 9。**どちらも CPU だけ**で、
[14](14-REFERENCE.md) の参照器で測った。**本線を進めるのはカーネルの側**なので、
ここは結論だけを短く置く。

## 1. 平均 NLL — 4 本とも `oQ4e-g64` が低い

同じトークン列を両チェックポイントに流し、位置 t の logits が t+1 のトークンを
どれだけ当てているかを見る (`reference_forward.py --nll`。文章は `Scripts/qwen35/nll_texts.py` が作る)。**両者のトークナイザは
語彙 248,044 が完全一致**し、4 本とも同じ ID になることを確かめてから流した
(公式版だけ音声用の added token が 7 本多いが、本文には出ない)。

**実測(手元)** (CPU float32、1 本あたり forward 210〜266 s):

| 文章 | トークン | **oQ4e-g64** | 公式 MLX-4bit | 差 |
| --- | ---: | ---: | ---: | ---: |
| 日本語散文 | 207 | **2.578** | 2.610 | −0.032 |
| 日本語技術文 | 249 | **2.520** | 2.634 | **−0.115** |
| 英語技術文 | 186 | **2.923** | 2.973 | −0.050 |
| コード (Swift) | 200 | **1.298** | 1.316 | −0.019 |

**4 本すべてで oQ4e-g64 が低い。**差は 0.019〜0.115 nat で、いちばん開いたのは
日本語の技術文だった。方向は [02 §1](02-CHECKPOINTS.md) の予想どおり
(imatrix 校正 + embed / lm_head / shared expert / attention が 8-bit) だが、
**大きさはこの 4 本ぶんの数字であって、位置ごとの対比較は取っていない。**

**本線は `oQ4e-g64`。**品質がどの文章でも負けておらず、MTP と vision の実物も
入っている ([02 §1](02-CHECKPOINTS.md))。差 2.35 GB の対価はこれで説明が付く。
公式 MLX-4bit は「attention が一律 4-bit なので混在ビット幅の宿題
([13 §4-2](13-PHASE1-REPACK.md)) を踏まない」という利点を残すが、
**それは実装の都合であって品質の理由ではない。**

## 2. `in_proj_a` の実活性再測 — **まだ判定できない**

[10 §5](10-MLX4BIT-AUDIT.md) は合成入力 `x ~ N(0,1)` で「4-bit の `in_proj_a` は
**系統的に忘れっぽくする**」(mean Δg が全層で負、L0 では 1000 トークンで保持量 0.32 倍)
と出していた。参照器が実活性を落とすようになったので、同じ指標を
**実物の層入力**で取り直した (`Scripts/qwen35/in_proj_a_real.py`、参照は上流 bf16)。

**実測(手元)**、ただし**活性は 11 トークンぶんしかない** (fixtures が 11 トークンの
prompt から出たもの)。**数字だけ置く:**

| 層 | 源 | \|dW\|/\|W\| | α>0.5 の \|Δα/α\| 中央値 / p95 | mean Δg ± SE | head ごとの Πα 比 (11 tok) 最小 / 最大 |
| ---: | --- | ---: | ---: | ---: | ---: |
| 0 | 4-bit | 9.17% | 0.040% / 0.97% | +2.0e-03 ± 1.9e-03 | 0.921 / 1.816 |
| 0 | 8-bit | 0.70% | 0.002% / 0.05% | −5.0e-04 ± 2.0e-04 | 0.828 / 1.006 |
| 1 | 4-bit | 9.65% | 0.202% / 3.92% | +8.9e-03 ± 2.6e-03 | 0.273 / 3.341 |
| 1 | 8-bit | 0.76% | 0.027% / 0.25% | +5.3e-04 ± 3.6e-04 | 0.936 / 1.134 |
| 2 | 4-bit | 10.19% | 0.716% / 3.77% | +6.1e-03 ± 2.1e-03 | 0.521 / 3.456 |
| 8 | 4-bit | 10.13% | 0.162% / 1.95% | +9.4e-04 ± 7.1e-04 | 0.361 / 2.468 |
| 8 | 8-bit | 0.80% | 0.015% / 0.18% | +7.1e-05 ± 1.0e-04 | 0.980 / 1.023 |
| 28 | 4-bit | 10.99% | 0.404% / 3.82% | −4.3e-04 ± 2.4e-03 | 0.572 / 2.054 |
| 28 | 8-bit | 0.88% | 0.026% / 0.26% | −2.4e-04 ± 6.5e-05 | 0.938 / 1.030 |

読み取れること・読み取れないこと:

- **重みの誤差 (\|dW\|/\|W\|) は合成入力のときと同じ** — 活性に依らない量なので当然で、
  10 §5 の 4-bit の欄 (9.17% / 9.65% / 10.19% / …) と 3 桁一致する。**逆量子化と
  bf16 の突き合わせが正しいことの再確認**にはなっている
- **8-bit は実活性でも 1 桁以上安全。**11 トークンの Πα 比が 0.94〜1.03 に収まる層が
  多く、4-bit は同じ 11 トークンで 0.27〜3.46 に散る
- **「系統的に忘れっぽくなる」という 10 §5 の結論は、この活性では再現していない。**
  mean Δg の符号は層ごとにばらつき、大きさは SE と同じ桁で、**11 トークンでは
  偏りと散らばりを分けられない。**head ごとの散らばり (Πα 比の最小/最大) の方が
  桁で大きい

**やり残し:** 200 トークン級の `--dump` を取って測り直すこと。
[10 §5](10-MLX4BIT-AUDIT.md) の「4-bit なら `in_proj_a` / `in_proj_b` を 8-bit に
打ち直す」という決定そのものは動かない (費用 +2 MB、誤差 17 倍差) が、
**その理由を「偏り」と書いてよいかは未確定**。なお本線は `oQ4e-g64` (§1) で、
そちらは既に 8-bit なので**この宿題は本線を止めない**。
