# 13. 子サーバの引数で取れるもの — KV Q8_0 は通る。スロットの save / restore は厳密な延長のときだけ効く

実測: 2026-09-21、M3 Pro 18 GB、macOS 15、`iogpu.wired_limit_mb` = 14336。表記は [qwen38/01](../qwen38/01-Q2-FIRST-LIGHT.md) と同じ (実測 / 導出 / 未確認)。
回数は節ごとに書く。1 回の欄は数字だけで、解釈は書かない。[12](12-NATIVE-PORT-GAIN.md) §6 の 1 と 2。
バイナリ・会話・検査の引数は [11](11-GUI-WIRING.md) §6 と同じ (`TsugumiToolLoopCheck` は 2026-09-20 22:02 のビルド)。

## 0. 結論

1. **`-ctk q8_0 -ctv q8_0` で 14 ターン × 2 セットが通った** (§1、2 セット)。`answer`・`error` 28/28、Swapouts 合計 +0、終了後にプロセスなし。
   サーバの RSS の最大は 10.88 / 10.73 → 10.15 / 10.07 GB、空き率の最小は 16 / 19 → 23 / 25%。
   読んだトークンあたりの prefill は 86.6 / 87.7 → 86.7 / 87.2 tok/s。decode は 16.3 / 16.4 → 15.8 / 15.9 tok/s、MTP の受理は 81.5 / 79.9 → 80.7 / 78.8%。
   **`manifest.json` の `server_args` に入れた** (2026-09-21、ユーザー決定。§4-1)。
2. **スロットの save / restore は動く** (§2、KV f16 と Q8_0 で各 1 回)。15,728 トークンの状態が f16 で 1.19 GB・Q8_0 で 0.70 GB、save 0.14〜0.33 s、restore 0.15〜0.29 s、Swapouts +0。
   別の会話 (16,111 トークン) を挟んで restore した後、続きの要求は `cache_n` 15,728・prefill 0.8〜0.9 s (復元なしは 175.0 / 177.2 s)。
   続きの 1 トークン目の top-10 logprob は、切り替え前の値と小数 4 桁まで同じ。
3. **ただし、続きの要求が保存した状態の末尾より手前で食い違うと、restore しても `cache_n` は 0 になる** (§3、1 回)。
   切り替え前なら同じ要求は `cache_n` 15,525・2.6 s で済む (サーバの中のチェックポイントに戻っている)。restore の後は 176.1 s で、復元なしの 176.1 s と同じ。
4. **実ターンでは、新しいターンの最初のラウンド 32 回のうち 26 回が厳密な延長、6 回が 608〜1,298 トークン手前で食い違っていた** (§3-1、11 §6 と §1 の 4 セットの記録)。
   食い違う 6 回は ja-news と ja-howto の 2・3 ターン目。何が食い違っているかは読んでいない (未確認)。
5. **save / restore はアプリに入れない** (2026-09-21、ユーザー決定。効くのは複数のチャットを行き来するときだけ)。12 §3 の表の「前の会話に戻ったときの prefill」は、**引数だけでは取りきれない**。アプリ側に save / restore の呼び出しが要り、
   それを入れても 4 の 6/32 は全部読み直しになる。

## 2. スロットの save / restore (実測、KV f16 と Q8_0 で各 1 回)

`Scripts/qwen38_27b/bonsai_slot_save_check.py OUT`。manifest の引数に `--slot-save-path` を足したサーバ 1 つに、素の `/v1/chat/completions` を順に送る

サンプリングは公式値のまま。「続き」は A + A の回答 + 次の質問。

## 3. 続きが手前で食い違う場合 (実測、KV f16、1 回)

同じスクリプトに `--diverge 120`: 続きの要求で、A の回答の末尾 120 文字を別の文に替える (履歴の描き直しが、保存した状態の末尾より手前で変わる形)。

| 要求 | `prompt_n` / `cache_n` / prefill |
| --- | --- |
| 続き (切り替え前) | 171 / 15,525 / 2.6 s |
| **続き (restore の後)** | **15,696 / 0 / 176.1 s** |
| 続き (復元なし) | 15,696 / 0 / 176.1 s |

- 3 つとも 1 トークン目の logprob は同じ (`ご` −0.9022・`3` −0.9891・`第` −3.5777)。
- restore の後の要求でも、サーバログは `f_keep = 0.996` でスロットを選んでいる。そこから全部を読み直した理由を示す行は、ログに無い。
- `--ctx-checkpoints` (既定 32) が作るチェックポイントが保存ファイルに入るかどうかは、コードでは確かめていない (未確認)。上の表は「入っていない」場合と同じ結果。
