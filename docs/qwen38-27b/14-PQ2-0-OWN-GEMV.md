# 14. PQ2_0 の GEMV を自前で書いて llama.cpp と比べた — 上回らない (1 列で 1.05 倍、2〜4 列で 1.11 倍)

実測: 2026-09-21、M3 Pro 18 GB、macOS 15。[12](12-NATIVE-PORT-GAIN.md) §6-4 の 1 本。
表記は [qwen38/01](../qwen38/01-Q2-FIRST-LIGHT.md) と同じ (実測 / 導出 / 未確認)。回数は節ごとに書く。

## 0. 結論

1. **自前のカーネルは llama.cpp の `mul_mv_pq2_0` を上回らない** (§1、こちら 3 回・llama.cpp 2 回)。
   m=4096 / k=14336 で 1 列 135.0 対 128.7 us (1.05 倍)、2 列 209.6 対 188.5 (1.11 倍)、
   3 列 305.4 対 272.0 (1.12 倍)、4 列 397.2 対 358.1 (1.11 倍)。
2. したがって **12 §6-4 の分かれ目は「上回らない」側**に決まった。自前経路の decode で狙える分は
   12 §2 の「行列積の外の約 15 ms」の一部だけで、行列積そのものを速くして拾える分は無い。
3. ついでに、**リポジトリにあった PQ2_0 の GEMV は 1.40 倍速くなった** (189.5 → 135.0 us、1 列)。
   元の形 ([03](03-DENSE-KERNELS.md) の 10 型と共有) は 32 重みの小ブロックごとに活性 x を行の数だけ読み直していた。
   x をレジスタに載せて SIMD グループの行で使い回す形にした (§2)。`GGMLDenseGEMV` の PQ2_0 はこの 2 本に切り替えた。
   **これは自前経路のカーネルで、アプリが使っている子サーバ経路 ([11](11-GUI-WIRING.md)) の速さは変わらない。**
4. 実際の decode が何 tok/s になるかは測っていない (**未確認**)。Bonsai のランナー結線は無いままで ([05](05-BONSAI-PQ2-0.md) §10)、
   ここで比べたのは行列積 1 本の GPU 時間だけ。

## 2. 何を変えたか (`Sources/Tsugumi/Metal/Quant/ggml_iq.metal`)

- 03 の共有の形: 1 レーンが 32 重みの小ブロックを担当し、行ごとに `DEQ` で 32 個の重みを float に開いて掛ける。
  活性 x の 32 個は**行の数だけ読み直す** (1 SIMD グループ 4 行なら 4 回)。
- 足した形 (`ggml_pq2_0_gemv_rows<R, WPL>`): x の `WPL` 個を先にレジスタに載せ、SIMD グループが持つ `R` 行で使い回す。
  三値は逆量子化せず、llama.cpp の `mul_mv.metal` と同じく `(q - 1) * x = bit0 * x + 2 * bit1 * x - x` の 3 項に分ける。
  行の端は行番号を `min(row0 + r, M - 1)` に丸めて読み、書き戻しで落とす (m=4100 でも一致、§3)。
- 残したのは `_r4` (32 重み × 4 行) と `_r8w16` (16 重み × 8 行) の 2 本。`GGMLDenseGEMV` は 1 列で `_r4`、
  2 列以上で `_r8w16` を選ぶ。

落としたもの (どれも §1 の形で 1 回ずつ測って負けた):

| 形 | 1 列 | 2 列 |
| --- | ---: | ---: |
| 32 重み × 8 行 | 158.4 | 235.0 |
| 16 重み × 4 行 | 242.5 | 433.5 |
| 16 重み × 16 行 | 151.4 | 259.3 |
| `_r4` の x を `float4` で読む | 136.0 | 219.0 |
| `_r8w16` の x を `float4` で読む | 149.0 | 219.1 |

`float4` の 2 本は元と 1% 以内で、差が無いので消した ([08](08-PP-TG-CEILING.md) §4 の `packed_uchar4` と同じ結果)。

## 3. 正しさ (実測)

- `--pq2-gemv-bench` は形ごとに、同じバイト列を double で掛けた値と比べる。3 本とも相対誤差 1.3e-7〜2.1e-7 (閾値 1e-5)。
  m=4100 (8 でも 16 でも割り切れない) でも通るので、端の行の丸めは効いている。
- 03 の 10 型は触っていない。`--q27-dense` の 52 本は PASS のまま (実測、1 回)。
- ここで比べたのは**合成の重み** (2 bit の 0/1/2 と fp16 の scale を乱数で作ったもの) で、GGUF の実データではない。
  実データでの一致は 05 §2-1 (復号のビット一致) と、今回は取っていない。
