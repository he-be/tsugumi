# 再設計: ハーネスに入れて初めて測れるもの

作成: 2026-09-16。README.md（v1、知識源 3 通り × 5 条件 × 24 問）を、記事の主張から組み直したもの。
v1 の環境・ハーネス改修（README.md §3）・web-store・手順はそのまま使う。変えるのは問い、モデルの組、条件、問題数、図。

## 1. 記事の主張

前の 2 本で、毎日の用事を手元に移した。Gemini が名前も値段もそのままで中身だけ入れ替わるのが嫌で、
Claude Code と共通の枠をレシピで削るのも嫌だった。メモリ 16GB の Mac に載る一番賢いものとして
Gemma 4 26B を選び、専用のアプリを書いて、このひと月は何でもそれに聞いている。

手元に持つというのは、勝手に中身が変わらない代わりに、勝手に良くもならない、ということだ。
だから所有には続きがある。**お抱えの AI を最新に保つとは、LLM が進歩するたびに、そのとき自分の機材に
載る一番賢いものへ、自分の手で載せ替え続けること**だ。載せ替えの判断は、こちらの仕事になる。
その値打ちの上限は「その機材に載る一番賢いもの」で決まっていて、そこが長いあいだ 26B だった（§2）。
前記事でその上限が動いた。総 177B の Qwen3.8-Flash-Next が 18GB の Mac で回った。
7 倍の知識が同じ機械に載る。ただし 4 倍遅い。乗り換えるべきなのか。記事はこの判断の記録の形をとる。

物差しを間違えると、何も見えない。Ollama に一行投げて答えを眺める使い方で出てくるのは、
合っているかと、毎秒何トークンか、の二つだけだ。

○× では差が出ない。知識カットオフはどちらも古く、最近の出来事は大きい方も小さい方も揃って知らない。
実際、道具なしの新しい 5 問は両方とも全滅した。

t/s は 40 と 10 で 4 倍違う。これだけ見れば結論は出ているように見える。だが実験の待ち時間はそう動かなかった。
道具なしの 10 問で、Gemma 53 秒、Qwen 49 秒。ほぼ同じだ。4 倍速い方が 4 倍喋っていた
（1 万トークン対 2,600）。とくに「日本で一番東の駅は」の 1 問に 37.8 秒・9,500 字を使い、
中身は実在しない駅名のループだった。速いモデルが速く終わるとは限らない。

道具を持たせると、今度は 4 倍以上に開く。Web つき 5 問で Gemma 42 秒、Qwen 194 秒。
ただしその差の出どころは t/s だけではない。Qwen は 12 万トークン読んで 26 ラウンド回し、
Gemma は 4.2 万トークン・15 ラウンドで終えている。読んだページは 12 と 5。
**遅さには、余計に読んで余計に往復した時間が上乗せされている**（素の速度差は約 3 倍、待ち時間の差は 4.7 倍）。そして余計に読んだ分がそのまま答えの中身になっている。
RAM の値段を聞いた回は、Gemma が 8 秒で数字のない一般論、Qwen が 48 秒で四半期ごとの上昇率まで出した。

逆向きの例もある。オフラインの旅券の問いで、Gemma は 2.1 秒で答えた。全条件で最速のこの回答は、
Wikipedia を一度も引かずに作った嘘だった。速さは、調べていないことの証拠でもある。

「30 t/s 出ないと実用にならない」はコーディングの物差しだ。コードは大量のトークンを吐かせる作業で、
生成速度がそのまま作業時間になる。この記事が扱う調べ物では、モデルが吐くのは検索語と数百字の答えだけで、
Qwen の 194 秒の内訳は読み込み 87 秒・生成 89 秒とほぼ半々だった。読み込み側は t/s とは別のハードで決まる
（Mac ではプレフィル 90 t/s が壁になる）。物差しが違う。

知識の差が出るのは、道具を持たせて往復させたときだ。前記事にこう書いた——Gemma は検索結果をちゃんと読む。
弱いのは読む前と読んだ後で、質問をどう受け取るか、どれを開くか、読んだ中のどの一行を本題と見るか。
そこは元から持っている知識で即答するしかない。知識は答えではなく段取りに出る。
段取りはハーネスの中でしか見えないし、段取りをすれば遅くなる。

一行でいうと、手元の LLM にやらせているのは一問一答ではなく、探して、読んで、答える仕事で、
その値打ちはハーネスに入れて初めて測れる。単発のリクエストで比べている限り、
4 倍遅い方に乗り換える理由は一行も書けない。

**この主張から出る縛り**

- 正答率の一覧表を主図にしない。○× は「単発では差が消える」の例示だけに使う。
- 速度は t/s ではなく、ラウンド数・読んだトークン・吐いたトークンで書く（§6）。
  数字は実験機の GPU のもので Mac の時間ではない、と断る（素の生成速度の比は 211 : 65 で、Mac の 40 : 10 とほぼ同じ）。
- 「総パラメータが知識、アクティブが速度と置き場所」という仕組みの話は §2 の材料として一度だけ触れる。冒頭に置かない。
- 導入は所有の話から入る。クラウドは向こうが中身を替え、ローカルは自分で替える。記事はその載せ替えの判断。
- 「120B 前後が最適な帯」も実験ではなく §2 の表（何が無かったか）で言う。

## 4. 記事で断ること

- G26 → QFN の差は世代とサイズを分けられない。「今まで使っていたもの」と「今いちばん薦めるもの」の差として書く。
- QFN は IQ3_XXS、Gemma は Q4_0。
- Nemotron 3 Super は重いので試していない。
- 10 問は自分の使い方の分布で、ベンチマークではない。
- 秒数は LAN の向こうの GPU のもので、Mac の時間ではない。素の生成速度は 211 t/s と 65 t/s で、
  Mac の 40 と 10 とほぼ同じ比。Mac ではプレフィルが 90 t/s で頭打ちになるので、
  読み込み側の重さは実際にはもっと効く。
- 各条件 1 回。目立つ結果 5 つだけ 4 サンプルまで増やした（§7）。

### 待ち時間の中身（`rounds.jsonl`、条件ごとの合計）

秒数は LAN の GPU のもの（§4）。素の生成速度は G26 が 211 t/s、QFN が 65 t/s。

- **道具なしの待ち時間はほぼ同じ**（53.1s と 49.3s）。3 倍速い側が 4 倍喋っているため。
  うち N2 の 1 問が 37.8 秒・9,492 字のループで、これを除けば G26 15.3s / QFN 47.4s と素直に 3 倍。
- online の 4.7 倍差は、素の速度差（約 3 倍）に仕事量（読んだトークン 2.9 倍、ラウンド 1.7 倍）が乗ったもの。
- QFN online の内訳は読み込み 86.7s・生成 88.7s でほぼ半々。コーディングと違い、待ち時間の半分は t/s の外にある。
- 記事に使う対比:
  - S5-ram: G26 7.9s・1 ページ・数字なし / QFN 48.4s・4 ページ・四半期ごとの上昇率。
  - N5-passport（offline）: G26 **2.1s・ツール 0 回**で全条件の最速、中身は嘘 / QFN 20.4s・3 記事で正答。
    速さが「調べていない」ことの証拠になっている回。

online の G26 は 5 問とも 3 ラウンド。アプリが強制する検索 1 回とページ読み 1 回をこなして答え、**自分から調べ直したことが一度もない**。
QFN は 12 ページ読み、S4 と S5 で上限 6 を使い切った。offline の G26 の 1 ラウンド（N5）は、道具を持っているのに一度も引かなかった回。
