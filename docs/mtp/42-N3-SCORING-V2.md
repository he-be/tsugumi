## 2. 設計の根拠 — なぜこの形か

### 2a. 軸を足さない (41 §1a)

37 §3 の N3 は `register` の 2×2 を採点軸に足す設計だった。**足せない。**
38 §3 が `register` を `2^H` に置き換え、41 §1a が**その `2^H` すら入力ではない**ことを
実測した (同じプロンプト・`--seed` 違いの 3 本で `io/tok` が 23% 動く)。
**選べるのはプロンプトであって、出てくるトークン列ではない。**
⇒ プロンプトは v1 と同じ 1 本のままにする。

### 2b. 選べないものは共変量として記録する (N3 設計 2-3)

軸にできないなら、**run ごとに測って列にする。**使うのは全 run の footer に
既に載っている 2 つだけで、**追加の run もトレースも `2^H` の計算も要らない**:

**`decode hit=…%`** (expert キャッシュのヒット率) と **`io=…s`** (pread の総和。
**産出トークンで割って ms/tok に正規化する**) の 2 つ。

41 §1 が **GPU busy は register でもスロット数でも動かない** (25.4〜26.4 ms/tok) と
出しているので、**ばらつきはこの 1 変数でほぼ説明が付くはず**である。
付かなければそれが発見になる — **付かなかった (§4)。**

### 2c. 温度 0 は運用点ではない — それでも 0 で測る

運用点は temp 1.0 / top-k 64 / top-p 0.95 で、`--temperature 0` はそこから外れる
(40 §4-4)。**それでも採点は temp 0 で取る** — temp 1.0 では on と off が別のトークン列を
出すので、e2e 壁時計比が生成長のくじ引きになるからである。
**このスコアは運用点の温度で測った数字ではない。**(そして temp 0 でも長さは
完全には揃わなかった。§4)

### 2d. bs は 4 のまま — 39 §2 の「最適 bs=2」は採点条件の数字ではない

39 §2 の最適 bs=2 は **48 スロット / temp 1.0 / 192 tok / キャプションスイープ**の値で、
採点条件とは **4 つ条件が違う**。持ち込むと 40 §4-11 の落とし穴そのものになる。
採点条件で取られている 32 スロットの値は **27 §2c の bs=4** だけである。
⇒ **v2 は bs=4。**bs の議論は、v2 が切れた後に**採点条件の中で** A/B する。

### 2e. 反復は画像を増やす代わりにならない

**同じ画像を 3 回測ってもスコアの足元は増えない。**temp 0 では出力が決定論的で、
反復で動くのはマシンの状態だけだからである。中央値の n を増やすのは画像を増やすこと
なので、**8 枚 × 3 反復ではなく 16 枚 × 1 反復**にした。反復は別の仕事に充てる —
**1 枚目だけを先頭・中盤・末尾で 3 回**測り、**先頭 対 末尾 = 熱ドリフト検定**
(|差| > 5% ならスイープごと疑う。39 §3 の 4 つ目)、**3 本の幅 = 目盛り**
(これ以下の差を本文で読まない。36 §9g) とする。
**クールダウンは 10 秒で凍結**した (2026-08-20 のユーザー判断)。
正しかったかはドリフト検定が事後に示す (§5)。

## 4. 共変量との関係 — **予想は外れた。主犯は生成長である** (**実測**)

41 §6 は「GPU busy が register でもスロット数でも動かない以上、スコアのばらつきは
`io` の 1 変数でほぼ説明が付くはず。付かなければそれが発見である」と書いた。
**付かなかった。**

相関 (n=18 ペア)。**壁時計比**に対して **生成長比 (on/off) −0.910** /
`io` +0.282 / `hit%` −0.364。**t/s 比**に対して `io` −0.350 / `hit%` −0.047 /
生成長比 +0.164。

**壁時計比のばらつきの主犯は expert I/O ではなく、on/off の答えの長さの違いである。**
長さで切ると分布が別物になる:

| 部分集合 | n | 壁時計比 中央値 (sd) | t/s 比 中央値 (sd) |
| --- | ---: | ---: | ---: |
| 長さが完全に一致 | 6 | 1.411 (**0.066**) | 1.495 (0.070) |
| \|長さ比 − 1\| ≤ 5% | 10 | 1.411 (**0.069**) | 1.511 (0.063) |
| \|長さ比 − 1\| > 5% | 8 | 1.373 (**0.314**) | 1.567 (0.060) |
| 全 18 ペア | 18 | 1.392 (0.209) | **1.539 (0.064)** |

⇒ 3 つ読める。

1. **中央値は頑健だった。**長さが揃う 10 セルだけで取っても **1.411** で、
   全セルの **1.415** と 0.3% しか違わない。**スコアそのものは信用してよい。**
2. **セル 1 個の壁時計比は、半分近くが「どちらが長く答えたか」である**
   (sd 0.066 → 0.314、**4.8 倍**)。**個別セルの比を本文で引かないこと。**
3. **t/s 比は長さに汚れていない** (sd 0.064)。22 §5 が禁じたのは**絶対 t/s** であって
   同一セッションの t/s **比**ではない。**スコアと t/s 比は必ず並べて報告する。**

**なぜ長さが動くのか**は 25 §4 が既に持っている — top-1 マージンが競り合った位置で
ブロック経路とスカラー経路の argmax が反転し、そこから答えが分岐する。
**temp 0 でも on/off は同じ文章を書かない。**⇒ 記録すべき共変量が 1 つ増えた:
**`new_on / new_off`** (TSV には最初から在る)。

**予想が外れたこと自体は 41 §1 と矛盾しない。**GPU busy が不変なのは
**1 トークンあたり**の話で、e2e 壁時計は「1 トークンの費用 × トークン数」だからである。
不変な費用に可変なトークン数が掛かる以上、**e2e のばらつきは長さが支配する。**

## 5. ドリフトと目盛り — **10 秒クールダウンは足りていた** (**実測**)

`NO_FUSION_0401_001.png` を先頭・中盤・末尾で 3 回:

| | 順序 | 壁時計比 | t/s 比 |
| --- | --- | ---: | ---: |
| head | off/on | 1.077 | 1.589 |
| mid | off/on | 1.075 | 1.586 |
| tail | **on/off** | 1.054 | 1.549 |

- **熱ドリフト: off 側の t/s が 22.12 → 22.55 (+1.92%)。**38 §2-2 の +2.28% と
  同じ向き・同じ桁で、**39 §3 の 5% 判定に対して OK。⇒ 10 秒クールダウンで
  足りていた。**
- **目盛り: 同順序 2 本の再現幅は 0.16%。順序を入れ替えた 1 本は −2.06% ずれる。**
  ⇒ **繰り返しの雑音より順序効果のほうが 13 倍大きい。1 セルの分解能は約 2%** で、
  これ以下の差を本文で読んではいけない。順序は 16 セル全体では相殺されるが、
  **セル単位では相殺されない。**
- **目盛りに選んだ画像が、よりによって最悪の交絡セルだった** (長さ比 1.461、
  壁時計比 1.075 で 16 セル中の最小)。**目盛りとしては機能した** — 3 本が
  決定論的に同じ長さを出したので、上の 0.16% / −2.06% は読める。
  **v3 では長さの揃う画像を目盛りに選ぶこと。**

## 6. temp 0 のループをどう扱うか

greedy なのでターゲットがループに入ることがある。**投機は出力を変えない**ので
on/off の両方に同じように起き、原理上は比を壊さない。**それでも採点には使えない**:
繰り返し列は低エントロピーで受理長も `hit%` も跳ね上がり **MTP に有利へ偏る**こと、
25 §4 の argmax 反転で分岐した先で**片側だけがループしうる**ことの 2 つである。

22 §4 は「`--max-new` 到達は FAIL、データ点にしない」と既に書いていたが、
**v1 のドライバは印を付けるだけで中央値に入れていた。**v2 は実際に落とし、
落とした本数を必ず報告する (**今回は 0 本**)。長さが ±25% を超えて食い違うセルにも
印を付ける (落とさないが、その比は一部が長さの比である。§4)。

**repetition penalty は使えない** — 26 §2 のとおりサーバーは
`repetition_penalty != 1.0` の要求を素の decode 経路に退避させるので、
入れると on 側が投機無しになる。

## 7. 限界 (**未確認**)

1. **v1 との絶対値の連続性は無い** (画像が違う。ユーザー確定 2026-08-20)。
   27 §2c の 1.394 との 2% 差も、別の日・別の画像で ABBA も無い。
2. **温度は運用点ではない** (§2c)。**このスコアは temp 1.0 では再現しない。**
3. **スコアの定義が長さの分岐に開いている** (§4)。中央値は頑健だったが、
   それは 16 セル中 10 セルが 5% 以内に収まったからで、**画像セットを入れ替えると
   分岐の割合も sd も変わりうる。**e2e 壁時計比のまま行くか t/s 比を主にするかは
   **決めていない** (22 §5 は凍結。変えるなら基準を切り直す話になる)。
4. **1 セル = 1 反復** (目盛りの 1 枚を除く)。セルの分解能 2% は
   その 1 枚から取った値で、**他の 15 枚では確かめていない。**
5. **共変量の相関はどれも n=18 の弱い相関**で、符号以上は言えない。特に
   `corr(io, t/s 比) = −0.350` を 27 §2c の「スロットが少ないほど投機が効く」
   (スロット間の話) と混同しないこと — こちらは画像間の話である。
6. **bs=4 で固定した** (§2d)。採点条件での bs スイープは取っていない。
